Now the Performance — Why Improvements 1–6 Didn't Help
The permutation function runs 102 times per 4 KB encrypt (one per 243-trit rate block). Each run executes this inner loop:
typescriptfor (let i = 0; i < STATE_SIZE; i++) {       // 729 iterations

}
That's 3 function calls × 729 trits × 9 rounds × 102 squeezes = ~2 million function calls for a 4 KB encrypt. In V8, each function call has overhead — argument boxing, stack frame, return. The balancedWrap LUT itself is fast (one array access), but the call boundary kills it.
Plus: the ext array is reallocated and copied every round (line ext.set(state.subarray(STATE_SIZE - 13), 0) etc.) — that's 9 × 102 = 918 typed array copies per encrypt.
Improvements 1–6 cut overhead AROUND the permutation (fewer sponge inits, fewer MACs, fewer allocations). But the permutation itself — which is 95% of the cost — was never touched.
