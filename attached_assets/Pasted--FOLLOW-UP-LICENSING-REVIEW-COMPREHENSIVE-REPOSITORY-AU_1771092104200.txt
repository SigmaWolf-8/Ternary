4. Current Findings
F-1: Build Artifacts Re-Committed to Git (521 files, 226 MB)
Severity: CRITICAL
The 280 MB build artifact removal (commit f00cafa) was subsequently undone by the "Sync PlenumNET platform" batch commits, which re-added 521 files under src/kernel/target/. The .gitignore correctly contains **/target/ but this only prevents new additions — files already tracked are unaffected. The .git directory is 222 MB, with individual .rlib files exceeding 57 MB. GitHub imposes a 100 MB file size limit and warns at 50 MB. Every clone downloads this dead weight.
Remediation: Phase 0, Tasks 0-2 and 0-3. Remove from tracking, prevent re-addition.
F-2: CORS Middleware Bypass Bug
Severity: CRITICAL
In server/middleware/cors-config.ts, the CORS origin callback has identical logic in both branches: if the origin IS allowed, callback(null, true); if the origin is NOT allowed, also callback(null, true). This means CORS is effectively open to ALL origins, completely defeating the purpose of the allowed origins list. Any website can make authenticated cross-origin requests.
Remediation: Phase 0, Task 0-4. The else branch must call callback(new Error('Not allowed by CORS')) or callback(null, false).
F-3: Fuzz Crate Missing License Field
Severity: HIGH
File: src/kernel/fuzz/Cargo.toml
The fuzz testing crate has publish = false (so it won't appear on crates.io) but still lacks a license = "LicenseRef-Proprietary" field. While the publish flag provides some protection, completeness requires the field for consistency and to prevent any argument that fuzz targets were intended to be unlicensed.
Remediation: Phase 0, Task 0-1.
F-4: 52 Source Files Missing Copyright Headers
Severity: HIGH
Despite 269 files now having headers (136 Rust + 133 TS/TSX), 52 source files remain without the proprietary copyright header. Breakdown: 41 TypeScript files in the services/ directory (payment-listener, blockchain services, sfk-core-api, timing services), 4 libternary Rust files (tribonacci.rs, borromean.rs, ternary_circle.rs, integration_properties.rs), 2 client files (marketing-top-nav.tsx, use-page-title.ts), and 5 root config files (drizzle.config.ts, vite.config.ts, vitest.config.ts, tailwind.config.ts, postcss.config.mjs).
Remediation: Phase 1, Tasks 1-1 through 1-4.
F-5: License-Check CI Workflow Does Not Scan services/ Directory
Severity: HIGH
The license-check.yml workflow scans ternary-math/src/, src/kernel/src/, server/, client/src/, shared/, and libternary/src/ — but NOT the services/ directory, which contains 41 unhealthy files across payment-listener, blockchain services (Algorand, Hedera, XRPL), sfk-core-api, and timing services. These services contain cryptographic webhook validation, payment processing, and blockchain integration code that is arguably as valuable as the kernel.
Remediation: Phase 1, Task 1-5.
F-6: Encryption Key Derivation Uses Predictable Fallback
Severity: MEDIUM
File: server/crypto-utils.ts
The getEncryptionKey() function uses process.env.SESSION_SECRET or falls back to process.env.REPL_ID. REPL_ID is a static, publicly-visible Replit deployment identifier — it is not a secret. Any attacker who knows the REPL_ID (visible in Replit URLs) could derive the encryption key and decrypt all stored GitHub tokens. The function correctly throws if neither is set, but the fallback to REPL_ID undermines the security guarantee.
Remediation: Phase 2, Task 2-4. Remove REPL_ID fallback. Require SESSION_SECRET explicitly.
F-7: 207 Files in attached_assets/ (3.7 MB)
Severity: LOW
The attached_assets/ directory continues to grow and now contains 207 files totaling 3.7 MB. These include multiple timestamped drafts of legal documents, strategy notes, and pasted text snippets. During litigation discovery or IP due diligence, draft language that differs from final versions could create ambiguity.
Remediation: Phase 5, Task 5-3.

PART II: SECURITY & CODE QUALITY AUDIT
6. Security Assessment
SEC-1: CORS Bypass (Duplicate of F-2)
Severity: CRITICAL
See Finding F-2. The CORS middleware accepts ALL origins regardless of the allowedOrigins list. Both the if and else branches call callback(null, true).
SEC-2: Rate Limiting Implementation
Status: IMPLEMENTED
Four tiers of rate limiting are properly configured: global (100/min), auth (20/min), GitHub token (10/min), computation (50/min). The middleware files exist at server/middleware/rate-limiter.ts and are imported correctly in server/index.ts. The global limiter is applied to all /api/ routes.
SEC-3: Helmet.js Security Headers
Status: IMPLEMENTED
Helmet is configured with HSTS (1 year, includeSubDomains), X-Content-Type-Options, XSS protection, strict referrer policy. CSP is intentionally disabled (common for SPAs with dynamic content). Cross-origin resource policy is set to "cross-origin" for API consumers.
SEC-4: AES-256-GCM Token Encryption
Status: IMPLEMENTED WITH CAVEAT
GitHub tokens are encrypted at rest using AES-256-GCM with random 12-byte IVs. The encrypt/decrypt cycle is integrated into the storage layer. However, the key derivation uses a REPL_ID fallback (see F-6).
SEC-5: Path Sanitization
Status: HARDENED
The sanitizePath function in server/routes/middleware.ts now implements null-byte stripping, double URL-decode protection, backslash-to-forward-slash normalization, path.posix.normalize(), and post-normalization ".." rejection. This is a significant improvement over the original 3-line regex.
SEC-6: Command Injection Prevention
Status: FIXED
All child_process usage in server/routes/kong.ts now uses execFile() (no shell) instead of exec(). Zero instances of exec() remain in any route file.
SEC-7: Input Validation Bounds
Status: IMPLEMENTED
Batch timing limited to 1-100. Trit count limited to 1-1000. Data length limited to 1-10,000. Page size bounded to 1-1,000 with Math.min/Math.max.
7. Code Architecture Assessment
7.1 Route Decomposition
Status: COMPLETED
The monolithic server/routes.ts (previously 3,732 lines) has been decomposed into focused modules: routes.ts (923 lines, core routes and orchestration), routes/github.ts (547 lines), routes/kong.ts (1,367 lines), routes/salvi.ts (1,041 lines), routes/tribonacci.ts (126 lines, new), and routes/middleware.ts (53 lines). Total route code is 4,057 lines across 6 files, organized by domain.
7.2 Structured Logger
Status: IMPLEMENTED (Custom, not Winston)
server/logger.ts implements a 60-line custom structured logger with log levels (debug/info/warn/error), JSON metadata, ISO timestamps, module tagging, and safe error serialization. Zero console.log/error/warn calls remain in route files. Note: this is a custom implementation, not the Winston library. The CHANGELOG.md references "Winston" but the actual implementation is bespoke. This is functionally equivalent but should be documented accurately.
7.3 Centralized Environment Configuration
Status: IMPLEMENTED
server/config.ts provides typed configuration objects for port, database, session, and environment detection.
7.4 Error Handling
Status: CLEAN
Zero instances of catch(error: any) in any route file. All catch blocks use error: unknown with the toErrorMessage() helper.

10. GitHub API Push Protocol
Standard workflow for each file modification:
•	GET /repos/SigmaWolf-8/Ternary/contents/{path}?ref=main to obtain the current file SHA.
•	Base64-encode the new file content.
•	PUT /repos/SigmaWolf-8/Ternary/contents/{path} with body: { message, content (base64), sha, branch: "main" }.
•	For new files, omit the sha field.
•	For deletions, use DELETE with the file's current SHA.
Exception — Task 0-2: Build artifact directory removal requires git rm -r --cached from a local clone, followed by git push origin main. The Contents API cannot remove an entire directory tree atomically.
Commit Message Convention: fix(legal): for licensing; fix(security): for security; fix(repo): for repository hygiene; ci(): for CI changes; test(): for tests; docs: for documentation.
