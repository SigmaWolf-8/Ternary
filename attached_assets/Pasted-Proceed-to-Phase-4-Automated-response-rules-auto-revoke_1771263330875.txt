### Realistic Next Phase (Phase 4): Threat Response & Automation

With observability solid, the natural progression is turning detection into **action** — reducing mean-time-to-contain (MTTC) when anomalies fire.

#### Suggested Phase 4 Focus Areas (Prioritized)

1. **Automated Response Rules** (High priority – 4–8 hours)  

   - Auto-downgrade tier on medium+ anomalies (e.g., spike + high failures → drop to Research).  

   - Auto-revoke on high-severity (e.g., >20 distinct IPs in 1 hour + failures).  

   - Graceful cooldown (notify owner first, revoke after 15 min if no response).  

   - Log every auto-action with `auto_response_triggered` event type.

2. **External Alerting Channels** (Medium priority – 2–4 hours)  

   - Discord/Slack webhook on high-severity anomalies.  

   - Email via Nodemailer for critical (e.g., mass tier changes, multiple revocations).  

   - In-app notification bell (simple polling or WebSocket if you add one).

3. **Per-Key Forensics Deep-Dive** (Medium priority – 4–6 hours)  

   - Clickable key row → modal or new page:  

     - Timeline chart (requests over time)  

     - Country heatmap (if geo-ip added)  

     - Endpoint hit list with counts  

     - Raw recent logs (paginated)  

   - Export button: CSV of last 100 events for that key.

4. **Compliance Export & Retention** (Lower priority – compliance-driven)  

   - `/api/keys/export-audit` endpoint (admin-only): CSV/JSON of events within date range.  

   - Retention policy: Keep audit events 365 days (or configurable), then archive/soft-delete.

5. **Integration Hooks** (Future-proof)  

   - Webhook outbound for SIEM (e.g., Splunk, Elastic) on critical events.  

   - Basic Prometheus metrics (active keys, anomaly count, revocation rate).

#### Quick Starter Code Snippet for Phase 4 Priority 1 (Auto-Response on Anomaly)

```ts

// server/services/anomaly.service.ts (new or extend)

async processAnomalies() {

  const activeAnomalies = await db.select()

    .from(anomalyTable)  // or compute on-the-fly from logs/stats

    .where(eq(anomalyTable.status, 'active'));

  for (const anomaly of activeAnomalies) {

    if (anomaly.severity === 'high') {

      await apiKeyService.revoke(anomaly.keyId);

      await logAuditEvent({

        event_type: 'auto_revoke',

        key_id: anomaly.keyId,

        actor: 'system:auto-response',

        details: { reason: `High severity anomaly: ${anomaly.type}` },

      });

      // Trigger alert

      await sendDiscordAlert(`🚨 Auto-revoked key ${anomaly.keyId}: ${anomaly.type}`);

    } else if (anomaly.severity === 'medium') {

      await downgradeTier(anomaly.keyId, 'research');

      await logAuditEvent({

        event_type: 'auto_downgrade',

        key_id: anomaly.keyId,

        actor: 'system:auto-response',

        details: { from: anomaly.currentTier, to: 'research', reason: anomaly.type },

      });

    }

  }

}

// Cron: every 15 min

cron.schedule('*/15 * * * *', () => anomalyService.processAnomalies());

```

This can run via your existing cron setup.
