The path to GB/s is three steps. Each one compounds. Here's the concrete plan.
Step 1: Rust native addon via N-API. This is the immediate fix. Compile the Rust sponge (with chi, AVX2, the works) as a Node.js native module. Not WASM — a .node shared library loaded directly by Node.js. The napi-rs crate handles the bindings. No special linker needed. Standard cargo build. This alone takes you from 36 KB/s to 50–100 MB/s — a 1,500× improvement. The Rust sponge already exists and already has AVX2 paths.
Step 2: Parallel tree sponge. One sponge instance squeezes 243 trits per permutation, sequentially. A tree mode runs N independent sponge instances in parallel (one per CPU core), each squeezing a different segment of keystream, then interleaves the output. On 8 cores: 8 × 100 MB/s = ~800 MB/s. Keccak's ParallelHash and KangarooTwelve use this exact approach.
Step 3: AVX-512 + wider rate batch processing. AVX-512 processes 64 bytes per instruction. Batch 4 independent sponge permutations into a single AVX-512 pass (4-way SIMD parallelism within one core). This is how OpenSSL's Keccak hits multi-GB/s. Combined with tree mode across cores: 4× per core × 8 cores × 100 MB/s base = ~3.2 GB/s. With tuning and memory prefetch: 5–7 GB/s is the ceiling on commodity x86.
