## 1. Executive Summary

This matrix classifies every component of the Salvi Framework into one of four licensing tiers based on competitive sensitivity, commercial value, and strategic importance. The recommended approach is **full proprietary licensing** with the option to selectively open specific components in the future if ecosystem-building objectives emerge.

This document is an internal planning tool. It does not change the current licensing posture — all components remain under the proprietary license at the repository root until an explicit decision is made to the contrary.

---

## 2. Licensing Tier Definitions

| Tier | Classification | License | Rationale |
|------|---------------|---------|-----------|
| **Tier 0 — Crown Jewels** | Maximum Protection | Proprietary (All Rights Reserved) | Core competitive differentiators. Revenue-generating. Must never be open-sourced without board-level decision. |
| **Tier 1 — Strategic Assets** | High Protection | Proprietary (All Rights Reserved) | Significant IP value. Could theoretically be licensed commercially to third parties under separate agreement. |
| **Tier 2 — Enabling Infrastructure** | Standard Protection | Proprietary (current) / Source-Available (future option) | Valuable but not directly revenue-generating. Could be made source-available to build ecosystem trust without harming competitive position. |
| **Tier 3 — Ecosystem Candidates** | Conditional Openness | Proprietary (current) / Permissive (future option) | Foundational, non-differentiating components that could drive adoption if open-sourced. Decision deferred to post-revenue stage. |

## 5. Decision Framework for Future Licensing Changes

Before changing the license of any component from proprietary to source-available or open-source, the following criteria should be evaluated:

### 5.1 Gate Criteria (ALL must be met)

- [ ] **Revenue Impact:** Opening the component will not reduce revenue from existing or planned commercial offerings
- [ ] **Competitive Exposure:** Opening the component will not enable a competitor to replicate the platform's core value proposition
- [ ] **Patent Protection:** If the component contains patentable subject matter, patent applications have been filed before disclosure
- [ ] **Dependency Analysis:** The component can be cleanly isolated without exposing Tier 0/1 components
- [ ] **Brand Value:** Opening the component will generate measurable goodwill, developer adoption, or academic credibility

### 5.2 Approval Authority

| Tier Change | Approval Required |
|-------------|-------------------|
| Tier 3 → Open Source (MIT/Apache) | Division head + Legal review |
| Tier 2 → Source Available (EL2) | Division head + Legal review + Board notification |
| Tier 1 → Any less restrictive | Board approval + Patent review + Legal opinion |
| Tier 0 → Any less restrictive | Board approval (unanimous) + Patent filing confirmed + Independent IP valuation |
