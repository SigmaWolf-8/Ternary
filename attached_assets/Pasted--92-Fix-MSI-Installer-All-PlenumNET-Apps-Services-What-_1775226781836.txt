#92 - Fix MSI Installer — All PlenumNET Apps & Services
What & Why
The MSI installer is the single installer for ALL PlenumNET applications and services. Users downloading from the Replit app currently get a broken, incomplete version that crashes on PowerShell 5.1 and only installs 1 of 3 products. Two QC rounds (6 agents, 22 findings, 5 CRITICAL) identified the full scope.

Products That MUST Be Installed
PlenumNET Launcher — system tray hub (tray_agent, autostart)
NinjaExec — local signing agent (tray_agent, autostart)
Inter-Cube Daemon — Array3 daemon service (fundamental core service)
Root Causes
Two divergent installer scripts — served version (724 lines) has 1 product, root version (527 lines) has 3. Users get the incomplete one.
Unicode em dashes crash PowerShell 5.1 when downloaded.
NinjaExec passphrase exposed via environment variable instead of ACL-protected temp file.
Inter-Cube Daemon has no plenum-app.toml manifest — needs one created so plenum-pack can build it.
No re-divergence prevention — nothing stops someone editing the wrong copy.
Done looks like
client/public/install/install-plenumnet-msi.ps1 is DELETED
Express route serves root install-plenumnet-msi.ps1 directly
Root $Products contains ALL 3 products: PlenumNET-Launcher, NinjaExec, Inter-Cube Daemon
Root $allCrates contains ALL 4 crates: plenum-launcher, plenum-launcher-elevate, inter-cube, ninja-exec
services/inter-cube/plenum-app.toml CREATED with kind = "service" manifest for daemon
All Unicode em dashes replaced with ASCII in executable lines
$ErrorActionPreference = "Stop"
.bat wrapper: ASCII-only echo, paths-with-spaces safe UAC elevation
NinjaExec manifest first_run uses temp file with ACL (not env var)
Pre-install summary banner shows ALL 3 products, their behavior, install paths, pauses for confirmation
Build phase completes for ALL products before any MSI install begins
Post-install summary includes uninstall instructions
Two-phase build-then-install prevents partial installations
