TDNS addresses are identity anchors. If someone forges an address, they impersonate a node. That needs cryptographic strength. But let me break down where speed actually matters vs where security matters:
Registration/classification — happens once per entity. Even the unoptimized kernel sponge at 16,658 ns is fine. 5,500 ns optimized is trivial. Security matters here, speed doesn't. Use kernel sponge.
Document signing, key derivation, certificates — obviously cryptographic. Kernel sponge.
Wire packet integrity — millions of packets per second on an already-authenticated connection. The connection is already secured by TL-DSA. You just need fast corruption detection. This is where TIS-27 earns its place — a ternary CRC equivalent, not pretending to be crypto.
Routing distance — pure Hamming math at 8 ns. No hash involved.
Repunit checksum — 67 ns integrity check, already deployed.
