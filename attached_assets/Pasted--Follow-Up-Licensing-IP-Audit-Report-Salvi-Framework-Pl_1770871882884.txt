## FINDING 1 — LICENSING-STRATEGY.md COMMITTED TO PUBLIC REPO (CRITICAL)

**Severity:** CRITICAL — Immediate action required
**File:** `/LICENSING-STRATEGY.md` (repository root)

The **Component Licensing Strategy Matrix** — an internal strategy document explicitly marked "INTERNAL STRATEGY DOCUMENT — Not for Public Distribution" — has been committed to the public GitHub repository. This file contains:

- **Crown Jewels designations** identifying Phase Encryption, HPTP, TL-KEM/TL-DSA, VM ISA, THDL, VM Constants, Tribonacci Constants, Salvi Epoch, and verifyTau() as "Tier 0" maximum-protection components
- **Competitive assessments** explaining *why* each component is valuable (e.g., "No equivalent exists in market. Potentially patentable")
- **Strategic intent** revealing which components "could be open-sourced in the future" (Tier 3) vs. which "must never be open-sourced without board-level decision" (Tier 0)
- **Approval authority matrix** revealing internal governance requirements (board approval, IP valuation thresholds)
- **Exact file paths** mapped to competitive sensitivity tiers — effectively a treasure map for any competitor wanting to understand which 30% of the codebase contains the differentiating IP

**Risk Assessment:** A sophisticated competitor reading this file knows:
1. Which components to focus reverse-engineering efforts on (Tier 0 list)
2. Which components are considered "commodity" and therefore safe to replicate (Tier 3)
3. That the Company is considering open-sourcing ternary-math, meaning they can wait rather than build their own
4. That Phase Encryption and HPTP are the primary monetization targets
5. That patent applications have not yet been filed (gate criteria includes "patent applications have been filed before disclosure")

**Immediate Action:** Remove this file from the repository. A `git rm` is insufficient — the file's entire history must be addressed. Because Git preserves history, the content remains accessible in prior commits. Options:
- **Minimum:** `git rm LICENSING-STRATEGY.md` + commit. Accepts that the historical content is recoverable.
- **Maximum:** Use `git filter-repo` or BFG Repo-Cleaner to rewrite history and purge the file entirely. This is a force-push that rewrites all subsequent commit hashes. Given 980 commits and no forks, this is feasible but disruptive.
- **Recommended:** `git rm` immediately (within the hour). Evaluate history rewriting over the next 48 hours based on risk appetite.

## FINDING 2 — DEPLOYED LEGAL DOCUMENTS ARE PRE-CANADIAN V1 VERSIONS (CRITICAL)

**Severity:** CRITICAL
**Files affected:** All legal documents in the repository

The legal documents committed to the repo are our **initial V1 drafts**, not the final Canadian-first versions produced after the comparative review. Specific deficiencies:

| Document | Missing Canadian Element | Impact |
|----------|------------------------|--------|
| **LICENSE** | Governing law says "laws of the jurisdiction in which Capomastro Holdings Ltd. is incorporated" — does not name Ontario or Canada. No Language clause (s. 55 Québec CPC). No EIPA reference in export control section. No industrial design mention. No patent(s) pending clause. | Governing law clause is ambiguous. A court could interpret "the jurisdiction" differently than intended. The explicit Ontario naming in the final version removes this ambiguity. |
| **PRIVACY-POLICY** | No PIPEDA references. No ten fair information principles. No Privacy Officer designation. No breach notification per s. 10.1 PIPEDA. No OPC contact. No Québec Law 25 rights. No CASL section. | For a Canadian corporation collecting personal information through a live SaaS, this is a **regulatory compliance gap**. PIPEDA requires a designated Privacy Officer and mandatory breach reporting. |
| **EXPORT-CONTROL-NOTICE** | No Canadian EIPA/ECL framework. No GAC Trade Controls Bureau. No GEP exemption analysis. No Area Control List. No SEMA sanctions. Only US EAR framework present. | A Canadian corporation's primary export control obligations arise under Canadian law (EIPA), not the EAR. The US framework is secondary and applies only to the extent the Software has a US nexus. |
| **CLA** | No moral rights waiver citing s. 14.1 of the Canadian Copyright Act. No Ontario governing law. No Language clause. | Under Canadian law, moral rights cannot be assigned — only waived. Without a proper waiver, contributors retain moral rights that could interfere with commercial exploitation. |
| **TERMS-OF-SERVICE** | No Ontario governing law. No attorn to jurisdiction. No PIPEDA reference. No CASL reference. No age of majority variations. Liability cap not in CAD. | TOS without Canadian governing law means the governing jurisdiction is undefined for the live SaaS. |
| **ACCEPTABLE-USE-POLICY** | No Criminal Code of Canada references. No SEMA/PCMLTFA. No CASL. | AUP should reference the criminal statutes of the Company's home jurisdiction. |
| **FILE-HEADER-TEMPLATE** | No "(Canada)" entity designation. No "Patent(s) Pending" notice. | Source file headers are the last line of IP defense when files are extracted from context. Every header should assert both jurisdiction and patent status. |

**Action:** Replace all committed legal documents with the final Canadian-first versions produced in our latest deliverable set.

## NEW IP REQUIRING PATENT ASSESSMENT

Since the initial audit, significant new innovations have been committed that should be added to the patent strategy:

### ADR-007: Carry Propagation as Computational Jerk
**File:** `docs/architecture/decisions/ADR-007-carry-as-jerk.md`
**Innovation:** Maps ternary carry propagation in base-3 addition to the physics concept of "jerk" (third derivative of position). Introduces a "Jerk Index" timing quality metric — carry propagation density of clock corrections. This creates a structural identity between ternary arithmetic complexity and timing protocol quality.
**Patent Assessment:** Strong. The jerk index as a timing quality metric is novel. Combined with the 364° ternary circle, this creates a closed system of ternary-native timing mathematics with no obvious prior art.

### Borromean XOR Invariant
**File:** `ternary-math/src/borromean.rs`
**Innovation:** Validates three-party cryptographic protocols using Borromean ring topology expressed in ternary logic. Representation-agnostic across A/B/C encodings.
**Patent Assessment:** Moderate-Strong. The application of Borromean rings to ternary cryptographic validation may be novel. Prior art search recommended.

### Ternary Circle (364° / π=14 / Z₂₈)
**File:** `ternary-math/src/ternary_circle.rs`
**Innovation:** A canonical angular system where a full circle is 364° = `111111₃`, π = 14, one radian = 13° = `111₃` = T₇, and the cyclic group Z₂₈ provides 28 discrete angular positions. This is not an approximation — the values are self-consistent within the ternary system.
**Patent Assessment:** Strong as a method claim when applied to the timing and navigation subsystems. The Z₂₈ phase correction lattice combined with the jerk index creates a ternary-native timing correction methodology with no prior art.

### Tribonacci Generator with Carry-as-Jerk
**File:** `ternary-math/src/tribonacci.rs`
**Innovation:** Tribonacci sequence generator with A/B/C interchange support and carry-as-jerk tracking.
**Patent Assessment:** Part of the broader Tribonacci-derived constant architecture claim.

**Recommendation:** These innovations should be added to the Tier 1 filing list in the Patent Strategy Memorandum. The carry-as-jerk / ternary circle / Z₂₈ phase correction complex is arguably a single patentable invention with multiple claims. Given the one-year Canadian grace period, the filing clock started when these files were committed publicly. **Patent counsel should review the commit dates for these files immediately.**
