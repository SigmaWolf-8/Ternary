## Overview

Five new endpoints are required to fully wire the Array3 Interactive Monitor to live infrastructure. Each spec includes the HTTP route, Axum handler signature, response struct, JSON shape, and placement within the existing crate structure.

**Priority order:**
1. **Slot Inventory** — unlocks the entire tunnel grid (highest impact)
2. **Relay Throughput** — enables live traffic visualization on relay tubes
3. **TL-DSA Signing Stats** — security audit visibility per slot
4. **YODA Agent Metrics** — multi-agent orchestration monitoring
5. **LLM Detailed Health** — inference performance visibility

### Deployment Agnosticism

All values in these specs are runtime-derived. Nothing is hardcoded.

- **Base URLs** are resolved from node configuration — the monitor discovers them via the relay's `cluster-health` response, which provides each node's `endpoint` and `port`.
- **Ports** are computed from `BASE_PORT` + offsets defined in the node's configuration (constants in `plenumlan/src/cube/constants.rs`). The monitor never assumes specific port numbers.
- **Node addresses** are the node's own identity (the 13-trit Rep C address from its identity file). The monitor reads these from API responses, never from constants.
- **Service types** are auto-discovered from whatever is actually running. If a new service type appears in slot data, the monitor picks it up automatically — no code change required.
- **Agent counts, model names, GPU hardware** — all read from the endpoint at runtime. Zero assumptions about specific hardware, model files, or pool sizes.

The JSON examples below use placeholder notation (`<description>`) for all runtime-derived values.

## Endpoint 1: Slot Inventory

**Why:** The monitor currently uses mock data for the 27-slot grid. This endpoint replaces all mock data with the real slot topology per node — which tunnels exist, what's running in each, and their status.

### Route

```
GET /api/salvi/inter-cube/slots
```

**Scope:** Per-node (served by each node's daemon on its configured `CUBE_API_PORT`)

### Axum Handler Signature

```rust
// File: services/inter-cube/src/routes/slots.rs (new file)

use serde::Serialize;

#[derive(Serialize, Clone)]
pub struct SlotInfo {
    /// Rep C address as [trit1, trit2, trit3], each in {1,2,3}
    pub rep_c: [u8; 3],
    
    /// Derived port for this slot (BASE_PORT + computed offset)
    /// The monitor displays this but never computes it — the daemon owns 
    /// the port derivation logic
    pub port: u16,

    /// builds its filter dropdown from them. No hardcoded type list.

    pub is_primary_gateway: bool,
```

## Endpoint 2: Relay Throughput

**Why:** Relay tubes need real traffic data for pulse rate and brightness.

### Route

```
GET /api/salvi/inter-cube/relay/throughput
```

**Scope:** Cluster-wide (relay server)

### Response Struct

```rust
#[derive(Serialize)]
pub struct RelayThroughputResponse {
    pub total_messages_relayed: u64,
    
    /// Breakdown by message type — HashMap, not enum.
    /// New types appear automatically.
    pub by_type: HashMap<String, u64>,
    
    /// Messages in rolling window
    pub messages_recent: u64,
    
    /// Window size so monitor can compute rate
    pub window_seconds: u64,
    
    pub uptime_seconds: f64,
    
    /// Per-pair throughput — pairs discovered from traffic
    pub pair_throughput: Vec<PairThroughput>,
}

#[derive(Serialize)]
pub struct PairThroughput {
    pub from_address: String,
    pub to_address: String,
    pub messages_recent: u64,
    pub bytes_recent: u64,
}
```

### Implementation Note

Expose existing internal counters. Use `HashMap<String, u64>` for `by_type` so new message types appear without schema changes. Sliding-window ring buffer for `*_recent` fields.

## Endpoint 3: TL-DSA Signing Stats

**Why:** Security audit visibility — which slots sign heavily, which have gone silent.

### Route

```
GET /api/salvi/inter-cube/tldsa/stats
```

**Scope:** Per-node

### Response Struct

```rust
#[derive(Serialize)]
pub struct TlDsaStatsResponse {
    pub total_signing_events: u64,
    pub total_verification_events: u64,
    
    /// Only includes slots that have signed at least once.
    /// Monitor infers 0 for missing slots.
    pub per_slot: Vec<SlotSigningStats>,
    
    pub uptime_seconds: f64,
    pub window_seconds: u64,
}

#[derive(Serialize)]
pub struct SlotSigningStats {
    pub rep_c: [u8; 3],
    pub port: u16,
    pub signing_events: u64,
    pub verification_events: u64,
    pub last_signed_at: Option<String>,
    pub signings_recent: u64,
}
```

### Implementation Note

`AtomicU64` counter in the TL-DSA signing module. Per-slot breakdown requires passing the caller's Rep C address to the signing function. Same sliding-window pattern as Endpoint 2.

## Endpoint 4: YODA Agent Metrics

**Why:** Agent pool status, task queue, QC pipeline for the YODA slot.

### Route

```
GET /api/agents/status
```

**Scope:** YODA service (on its configured port)  
**Auth:** Existing YODA auth guard

### Response Struct

## Endpoint 5: LLM Detailed Health

**Why:** Telemetry gives status and model name but no performance metrics.

### Route

```
GET /api/salvi/inter-cube/llm/health
```

**Scope:** Per-node

### Response Struct

```rust
#[derive(Serialize)]
pub struct LlmHealthResponse {
    pub reachable: bool,
    pub engine_status: String,       // Runtime string, not enum
    pub active_model: Option<String>, // From backend
    pub model_size_mb: Option<f64>,
    pub context_length: Option<u32>,
    pub tokens_per_second: Option<f64>,
    pub total_tokens_generated: Option<u64>,
    pub total_requests: Option<u64>,
    pub avg_latency_ms: Option<f64>,
    pub window_seconds: Option<u64>,
    pub gpu_pct: Option<f64>,
    pub gpu_name: Option<String>,    // Detected hardware
    pub gpu_vram_used_mb: Option<f64>,
    pub gpu_vram_total_mb: Option<f64>,
    pub backend_port: u16,           // From config
}
```

### Implementation Note

Proxy to LLM backend's health/metrics endpoint, merge with telemetry. All `Option` fields return `null` if the backend doesn't report that metric. Monitor shows "—" for nulls. Never fabricate values.

## Design Principles

1. **No hardcoded values.** Ports, addresses, model names, agent counts, service types, round names, capability tags — all runtime-derived.
2. **No fixed enums on the monitor side.** `service_type`, `engine_status`, `capability` — all free-form strings. Monitor auto-discovers.
3. **Nullable fields.** Every metric that might be unavailable is `Option<T>`. Monitor shows "—", never fabricates.
4. **Rolling windows are self-describing.** `window_seconds` accompanies every `*_recent` field so the monitor computes rates correctly.
5. **Rep C is the universal key.** All per-slot data keys on `rep_c`, not port numbers or indices.

## Monitor Wiring Architecture

```
┌──────────────────────────────────────────────────────────┐
│                   Array3 Monitor (HTML)                   │
│                                                          │
│  Discovery (bootstrap):                                  │
│    GET /relay/cluster-health → learn node addresses,     │
│    ports, roles. Build cube layout from response.        │
│                                                          │
│  Real-time (WSS):                                        │
│    wss://<relay-host>/ws/relay                           │
│    ├── telemetry → CPU, RAM, GPU, uptime, LLM status    │
│    ├── peers → connected nodes                           │
│    └── peer-offline → node dropped                       │
│                                                          │
│  Structural (REST, polled):                              │
│    GET /relay/cluster-health      (cluster topology)     │
│    GET /relay/throughput          (relay traffic)         │
│    GET /ops/status                (ops snapshot)          │
│                                                          │
│  Per-node (REST, via discovered addresses):              │
│    GET /slots                     (tunnel grid)          │
│    GET /con/stats                 (tunnel health)        │
│    GET /tldsa/stats               (signing audit)        │
│    GET /fts/status                (fault tolerance)      │
│    GET /crs/stats                 (registration)         │
│    GET /llm/health                (inference health)     │
│                                                          │
│  YODA (REST, on discovered YODA port):                   │
│    GET /api/health                (alive check)          │
│    GET /api/agents/status         (agent pool)           │
│                                                          │
│  Fallback:                                               │
│    Missing endpoint → "—" + "Awaiting: GET /slots"       │
│    Error/timeout → last good data + stale indicator      │
│    Never fabricate data.                                 │
└──────────────────────────────────────────────────────────┘
```
