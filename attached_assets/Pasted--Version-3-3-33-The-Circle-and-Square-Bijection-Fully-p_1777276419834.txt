## 2. Foundation: Bijective Base‑\(b\) Numeration and Repunits

Let \(b \ge 2\) be an integer (the base).  
**Bijective base‑\(b\)** uses digits from \(\Sigma_b = \{1,\,2,\,\dots,\,b\}\); the empty string \(\varepsilon\) represents \(0\).

### 2.1 Semantics and repunits

Every non‑empty digit string \(d_{L-1}\,d_{L-2}\,\dots\,d_0\) (most significant first) evaluates to  

\[
\boxed{\; \langle d_{L-1}\dots d_0\rangle \;=\; \sum_{j=0}^{L-1} d_j\,b^{\,j} \;}
\]

where the exponent \(j\) increases from right to left.

A string of \(L\) ones is the **repunit** of length \(L\):

\[
R_{L} \;=\; \underbrace{11\dots1}_{L\text{ digits}} \;=\; \sum_{j=0}^{L-1} 1\cdot b^{\,j} \;=\; \frac{b^{\,L}-1}{b-1}.
\]

The largest \(L\)-digit number (all digits equal to \(b\)) is \(b\cdot R_{L}\).

### 2.2 Length determination and bijection

For any positive integer \(N\), its unique bijective base‑\(b\) representation has length \(L\) given by the smallest positive integer satisfying  

\[
b\cdot\frac{b^{\,L}-1}{b-1} \;\ge\; N .
\]

Equivalently,  

\[
\frac{b^{\,L}-1}{b-1} \;<\; N \;\le\; b\cdot\frac{b^{\,L}-1}{b-1},
\]

with the left inequality void when \(L=1\). This condition guarantees a **bijection** between \(\mathbb{N}_0\) and all finite strings over \(\Sigma_b\).

### 2.3 The offset method (parallel extraction)

Once \(L\) is known, define the **offset** (the square to the repunit’s circle):

\[
X \;=\; N - R_{L} \;=\; N - \frac{b^{\,L}-1}{b-1}.
\]

Because \(0 \le X \le b^{\,L}-1\), \(X\) can be written in **standard base‑\(b\)** (digits \(0,\dots,b-1\)) with exactly \(L\) digits (leading zeros as needed):

\[
X = (a_{L-1}\,a_{L-2}\,\dots\,a_0)_b,\qquad a_j \in \{0,\dots,b-1\}.
\]

Adding 1 to each standard digit yields the bijective digits:

\[
d_j = a_j + 1 \qquad (j = 0,\dots,L-1).
\]

Thus the digit at position \(i\) (most significant first, \(i=0\) for the highest power \(b^{L-1}\)) is  

\[
\boxed{ \; d_i \;=\; \Biggl\lfloor \frac{X}{b^{\,L-1-i}} \Biggr\rfloor \bmod b \;+\; 1 \; } .
\]

Every digit is computed independently of any other — **fully parallel, stateless**.

### 2.4 Decoding

Given a bijective string \(d_{L-1}\dots d_0\),

\[
N = \sum_{j=0}^{L-1} d_j \, b^{\,L-1-j}.
\]

The offset is recovered as \(X = N - R_{L} = \sum_{j}(d_j-1) b^{\,L-1-j}\).

## 3. Bijective Base‑256: Bytes ↔ Integer  

A byte (0…255) is lifted to a digit \(b_j+1 \in \{1,\dots,256\}\), forming a bijective base‑256 string.

### 3.1 Bytes → integer  

\[
\boxed{ N \;=\; \sum_{j=0}^{L_{\text{bytes}}-1} (b_j+1) \; 256^{\,L_{\text{bytes}}-1-j} } \qquad (L_{\text{bytes}}=0 \Rightarrow N=0).
\]

This is a bijection from all finite byte strings onto \(\mathbb{N}_0\).

### 3.2 Integer → bytes (repunit‑based inverse, retained for spec completeness)

For \(N=0\), output the empty byte list.

For \(N>0\):

1. **Find the number of bytes \(L_{\text{bytes}}\)** as the smallest positive integer such that  

   \[
   256 \cdot \frac{256^{\,L_{\text{bytes}}}-1}{255} \;\ge\; N .
   \]

2. **Compute the offset**  

   \[
   X = N - \frac{256^{\,L_{\text{bytes}}}-1}{255} \qquad (0 \le X \le 256^{\,L_{\text{bytes}}}-1).
   \]

3. **Extract the standard base‑256 digits of \(X\)** (padded to length \(L_{\text{bytes}}\)):  

   \[
   a_i = \Biggl\lfloor \frac{X}{256^{\,L_{\text{bytes}}-1-i}} \Biggr\rfloor \bmod 256 ,\qquad i = 0,\dots,L_{\text{bytes}}-1.
   \]

4. **The original bytes** are exactly these standard digits:  

   \[
   b_i = a_i .
   \]

This mirrors the repunit‑offset method of Section 2.3 and guarantees correct bijection.

## 4. Encoder: Bytes → Trits and Glyphs (Fully Parallel, Parametric, Universal Glyph Output)  

**Input:** byte string \(\mathbf{B}\), representation \(R \in \{A,B,C,D\}\), block size \(k \ge 1\).  
**Output:**  
- A **trit sequence** in rep‑\(R\), length always a multiple of \(k\).  
- A **Milesian glyph string**, which is the bijective base‑27 representation of the integer \(N\) using the 27‑symbol Milesian alphabet (ghosts included). This glyph string is **always produced**, for every \(k\).

---

### 4.1 From bytes to integer \(N\)

Compute \(N\) as in Section 3.1. If \(N=0\), output the empty trit string and the empty glyph string.

### 4.2 Determine the number of base‑\(B\) digits \(D\) (for the trit stream)

With \(B = 3^{k}\), find the smallest positive integer \(D\) satisfying  

\[
\frac{B\,(B^{\,D}-1)}{B-1} \;\ge\; N .
\]

(This is the repunit bound of Section 2.2.)

### 4.3 Offset and digit extraction (for the trit stream)

\[
X = N - \frac{B^{\,D}-1}{B-1} \qquad (0 \le X \le B^{\,D}-1).
\]

The bijective base‑\(B\) digits (most significant first) are

\[
\boxed{ d_i \;=\; \Biggl\lfloor \frac{X}{B^{\,D-1-i}} \Biggr\rfloor \bmod B \;+\; 1 } \qquad (i = 0,\dots,D-1).
\]

Every digit is computed independently — no sequential dependencies.

### 4.4 Expansion to trits (block of \(k\) trits per base‑\(B\) digit)

Each base‑\(B\) digit \(d \in \{1,\dots,B\}\) is expanded into exactly \(k\) trits in **Rep‑C**.  
Let \(d-1\) be expressed in standard base‑3 with exactly \(k\) digits (pad on the left with zeros):

\[
d-1 = (q_{k-1}\,q_{k-2}\,\dots\,q_0)_3, \qquad q_j \in \{0,1,2\}.
\]

Then the \(k\) trits for this digit (most significant first of the block, i.e. \(t_0\) corresponding to the \(3^{k-1}\) place) are  

\[
t_{j}^{[C]} = q_{k-1-j} + 1 \qquad (j = 0,\dots,k-1).
\]

Concatenate the trit blocks of all digits in the same order as \(d_0,\dots,d_{D-1}\) to obtain the complete Rep‑C trit string. Its total length is \(k \cdot D\), always a multiple of \(k\).

### 4.5 Milesian Glyph String (always produced)

Independently of \(k\), compute the **bijective base‑27 representation** of \(N\) using the exact same offset method with base \(B' = 27\).  
Let \(M\) be the number of base‑27 digits (0 if \(N=0\)). For \(N>0\), find the smallest \(M\) such that

\[
27 \cdot \frac{27^{\,M}-1}{26} \;\ge\; N ,
\]
\[
X' = N - \frac{27^{\,M}-1}{26},
\]
and extract the base‑27 digits
\[
d'_i = \Bigl\lfloor \frac{X'}{27^{\,M-1-i}} \Bigr\rfloor \bmod 27 \;+\; 1 \qquad (i = 0,\dots,M-1).
\]

Map each digit \(d'_i\) to its corresponding Milesian glyph according to the table in Section 1. The resulting sequence of \(M\) Unicode characters is the **MilesianGlyphString**, which is output together with the trit string.

For \(N=0\), the glyph string is empty.  

Because the base‑27 representation is a bijection, the glyph string alone is also a perfect, waste‑free encoding of the original bytes. The trit string provides the chosen block‑packed view; the glyph string is the eternal Milesian name.

### 4.6 Representation mapping

Apply the chosen affine shift \(\phi_R\) to each Rep‑C trit to obtain the final output trits in the desired representation:

\[
\tau^{[R]}_j = \phi_R(t_j^{[C]}).
\]

The glyph string is always based on the canonical Rep‑C digits (the base‑27 digits mapped to glyphs), not on the shifted representation.

## 5. Decoder: Trits or Glyphs → Bytes (Stateless Inverse)  

The decoder can accept either the trit sequence (in any representation) **or** the Milesian glyph string (for any \(k\)), and recover the original byte string.

1. **If input is a glyph string:** Convert each glyph to its base‑27 digit using the inverse table. This yields the digit sequence \(d'_0,\dots,d'_{M-1}\). Recover \(N\) via
   \[
   N = \sum_{i=0}^{M-1} d'_i \; 27^{\,M-1-i}.
   \]
   Proceed to step 4.

2. **If input is a trit sequence:**
   - Shift back to Rep‑C using \(\phi_R^{-1}\).
   - Group the Rep‑C trits into \(D\) blocks of \(k\) trits each, most significant block first. Reconstruct each base‑\(B\) digit:
     \[
     d = \sum_{j=0}^{k-1} (u_{k-1-j} - 1)\cdot 3^{\,j} \;+\; 1 .
     \]
   - Recover \(N\):
     \[
     N = \sum_{i=0}^{D-1} d_i \; B^{\,D-1-i}.
     \]

3. **Convert \(N\) to bytes** using the bijective base‑256 inverse from Section 3.2.  

Round‑tripping is exact because every path is a bijection.
