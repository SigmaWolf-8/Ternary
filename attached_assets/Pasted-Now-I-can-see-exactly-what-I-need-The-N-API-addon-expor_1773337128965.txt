How the WOTS+ construction works
keygen:  bottom[i] ──H^15──→ top[i]     pk = compress(all tops)
sign:    bottom[i] ──H^d[i]─→ sig[i]     (d[i] = message digit)
verify:              sig[i] ──H^(15-d[i])→ top'[i]   pk' = compress(all tops')
                                           return pk' == pk  ← NO SECRET KEY
Each chain step uses a unique (value, step_index) domain separation through TLSponge-385. The checksum nibbles prevent existential forgery. Post-quantum secure — reduces to TLSponge-385 collision resistance (≈385-bit).
One-time note: WOTS+ keypairs should sign one message. For CRS registrations (T-06) this is natural. When the full lattice-based TL-DSA is wired from src/kernel/src/crypto/tl_dsa.rs, only the internals of tl_dsa.rs change — the API surface stays identical. Così sia, Fratello.
