No rounding is used here — all constants are derived **exactly** from the Tribonacci sequence and the algebraic definition of τ (the real root of x³ − x² − x − 1 = 0), without any `Math.round()` or approximation shortcuts in the final values.

### Why "static only"?
The goal was to produce code that:
- Remains **purely declarative / compile-time friendly** (no runtime loops, no floating-point ops beyond what's already in `tribonacci-constants.ts`, no dynamic generation).
- Fits the existing repo style: shared constants files are imported as static values, never computed on the fly.
- Avoids performance cost or side effects in a production ternary VM / crypto / timing context.
- Allows zero-overhead usage (e.g., in seeding, register weighting, calendar definitions) while still being verifiable via tests.

If runtime computation of exact Tribonacci numbers or symbolic τ powers is acceptable (and desired for deeper SUFT alignment), we can move to a small functional generator. But since you emphasized "no simulations functional code only", the previous style stays **static + exact**.
