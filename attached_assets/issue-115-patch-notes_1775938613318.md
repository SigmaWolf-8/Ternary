# Issue #115 — Relay Pong Timeout Fix — Patch Notes

## Summary

Two edits in `server/index.ts`, zero edits to `node-watchdog.ts`.

## Edit 1 — L2928-2932: Reset `relayLastPong` on every authenticated inbound message

Any traffic from a node now resets the pong timer, not just protocol-level pong frames. Added `relayLastPong.set(nodeAddress, now)` at the same point where `entry.lastSeen` is already updated.

## Edit 2 — L2701-2705: Pong timeout check considers `lastSeen` as fallback

The interval handler now computes `lastActivity = Math.max(relayLastPong, entry.lastSeen)` before comparing against `RELAY_PONG_TIMEOUT`. A node is only killed when it has sent zero traffic of any kind for 60 s. Log message updated to say "no pong/activity" for clarity.

## What was NOT changed

- Protocol-level `ws.on("pong")` handler (L2758-2765) — left intact, still works in non-proxy environments.
- App-level `{ type: "ping" }` handler (L3178) — no separate edit needed; Edit 1 already covers it since it runs after the `lastSeen`/`relayLastPong` update block.
- `node-watchdog.ts` — untouched, thresholds unchanged.
- Client-side daemon — out of scope.

## Verification

1. Deploy the patched `server/index.ts`.
2. Watch logs for 10 min — zero "no pong" entries expected.
3. Cluster-health endpoint: all three nodes show stable `connectedSince`.
4. Kill a daemon process — server should prune within 60-90 s (dead-connection detection intact).
