The overhead is rayon::join for the two-phase parallelism. Even on a single core, rayon still sets up its thread pool, does work-stealing coordination, and synchronizes. For small payloads that's slower than just running phase 1 then phase 2 sequentially.
The fix: check core count before touching rayon. If 1 core, never enter rayon at all — run the same v3 logic (independent MAC sponge, tree squeeze structure) but sequentially. No thread pool initialization, no coordination, no overhead. Same output, same security, zero parallelism cost.
