### 5.4 The Transfer Function Signature

```rust
enum Archetype { Sun, Gaia, Moon }

struct Register { column: Archetype, row: u8 }  // row ∈ 1..=13

enum ComposeOp {
    VectorSum,          // Part 3 Sun-Moon distance from Sun-Gaia + Gaia-Moon vectors
    VectorDifference,   // inverse of VectorSum
    ChainMultiply,      // sequential register applications
    NestedFulcrum,      // re-enter the transfer function at a sub-scale Fulcrum
}

trait RepXTransferFunction {
    fn at(&self, point: RepD, register: Register) -> RepD;
    fn emit(&self, point: RepD, registers: &[Register]) -> Vec<RepD>;
    fn rotate(&self, from: (Register, RepD), to: Register) -> RepD;
    fn compose(&self, readings: &[(Register, RepD)], op: ComposeOp) -> RepD;
}
```

- `at(x, R)` — emit the reading of displacement x in register R.
- `emit(x, [R₁, ..., Rₙ])` — one point, many readings, one pass.
- `rotate((R_src, value), R_tgt)` — the **RepD Transform**: given a reading in one register, emit the equivalent reading in another. Routes through Gaia for dimensional bridging when Sun↔Moon.
- `compose(readings, op)` — combine multiple register readings. `NestedFulcrum` re-enters the transfer function at a sub-scale Fulcrum (e.g. Gaia as Fulcrum within the Sun's field; Luna as Fulcrum within Gaia's field). `VectorSum` adds vector quantities across scales (e.g. Sun-Moon distance as Sun-Gaia ⊕ Gaia-Moon).

### 5.5 The RepD Transform — Sun ↔ Moon via Gaia

Given a Sun-column reading F_S at row r, the Moon-column reading F_M at the corresponding row is computed by routing through the Gaia-column entry that carries the shared dimensional bridge:

1. From F_S, invert to recover x in framework units (Sun entries are explicit functions of x; inversion is closed-form).
2. Evaluate the Gaia entry at that x (confirms the medium state at the point).

All three readings are Rep D coefficients. The entire chain stays in ℤ[ω]. No exit from the framework algebra.

### 6.2 Field Algebra in GF(3)

### 6.3 Eisenstein Algebra
Rep D in ℤ[ω] using `Trit::mul_eisenstein` / `Trit::eisenstein_add`:
- Add: coordinate-wise.
- Multiply: `(a₁+b₁ω)(a₂+b₂ω) = (a₁a₂ − b₁b₂) + (a₁b₂ + a₂b₁ − b₁b₂)ω` — closure folded in.
- Negate, square: closed-form specializations.

### 6.4 Parseval Energy
`parseval_energy(v: &[RepD]) -> TritInt`
1. For each `c_k = a_k + b_k ω`, compute `N(c_k) = a_k² − a_k b_k + b_k²`.
2. Sum in TritInt.

### 6.5 Nona Closure
`nona_closure(c₀, c₁, c₂: RepD) -> bool`
Compute `s = c₀ + ω·c₁ + ω²·c₂`. Via closure ω² = −1 − ω, reduces to `(c₀ − c₂) + ω·(c₁ − c₂)`. Zero iff `c₀ == c₁ == c₂`.
Alias: `is_balanced()`.

### 6.6 Nona DC

### 6.7 Horn Fixed Points

### 6.9 Pythagorean Chord Triple

Returns (chord(θ₁), chord(θ₂), chord(θ₁+θ₂)); satisfies a² + b² = c² when θ₁ + θ₂ subtends a right angle (182° framework / 180° standard).
