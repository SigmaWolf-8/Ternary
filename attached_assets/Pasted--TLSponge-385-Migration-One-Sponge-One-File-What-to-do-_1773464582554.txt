# TLSponge-385 Migration: One Sponge, One File

## What to do

1. Copy `tlsponge385.rs` to `ternary-math/src/tlsponge385.rs`
2. Add `pub mod tlsponge385;` to `ternary-math/src/lib.rs`
3. Delete the seven files listed below
4. Find-and-replace all call sites (see mapping)
5. Remove old module declarations from `lib.rs`
6. Build, test, bench

## Files to DELETE

```bash
# From ternary-math/src/:
rm ternary-math/src/sponge.rs            # Original scalar — absorbed into tlsponge385.rs
rm ternary-math/src/sponge_packed.rs      # GF(27) experiment — failed (16× slower)
rm ternary-math/src/sponge_2bit.rs        # 2-bit packed experiment — failed (101× slower)
rm ternary-math/src/sponge_dispatch.rs    # Dispatch layer — unnecessary with one sponge
rm ternary-math/src/sponge_fast.rs        # Prototype — absorbed into tlsponge385.rs
rm ternary-math/src/sponge_shuffle.rs     # σ shuffles — absorbed into sigma()
rm ternary-math/src/gf27.rs              # GF(27) arithmetic — absorbed into compile-time χ table
```

## TypeScript/Node.js callers

The N-API bridge calls into the Rust sponge. Update the bridge to point at `tlsponge385`:

```
// In the N-API binding (napi/src/lib.rs or similar):
// Change: ternary_math::sponge::derive_key
// To:     ternary_math::tlsponge385::derive_key
```

The TypeScript sponge fallback (`server/salvi-core/sponge.ts` or similar) is separate
and stays as-is — it's the JS fallback for when the native addon isn't available.
