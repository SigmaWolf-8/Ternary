#1 - Self-Hosted Model Install & PlenumNET Tunnel Button
What & Why
Add a single "Install & Connect" button to each Engine slot when self-hosted mode is active. Clicking downloads a platform-specific script that in one run:

Installs PlenumNET (clones Ternary repo, builds only inter-cube with --package inter-cube)
Starts inter-cube-daemon in cube mode → daemon calls out to YODA's CRS, tunnel is live immediately
Waits for and verifies tunnel registration with a status check
Installs Ollama and pulls the selected model (slow step — happens while tunnel is already up)
Starts Ollama serving locally (localhost:11434, never exposed publicly)
YODA on Replit runs the CRS side (inter-cube-daemon in crs mode). The server initiates outbound — no port-forwarding, no firewall rules needed. T-14 mutual auth handshake (TLSponge-385 HMAC / TL-KEM) happens automatically. Heartbeats every 30s keep the tunnel alive. YODA's GLB routes inference requests to the server through the established tunnel.

Cloud providers (Anthropic, OpenAI, xAI, Google, DeepSeek API) never show the button — those need only an API key.

Six issues resolved (from architecture review)
Issue 1 — CUBE_CRS_URL must not use window.location.origin
window.location.origin would embed localhost in dev builds, making the user's script point nowhere. Instead:

Add a VITE_CRS_URL environment variable set to the deployed .replit.app domain
The modal reads import.meta.env.VITE_CRS_URL for the embedded URL
If VITE_CRS_URL is unset (dev environment), the modal displays a warning: "CRS URL not configured — this script will only work when YODA is deployed"
Sub-task 3 must use import.meta.env.VITE_CRS_URL not window.location.origin
Issue 2 — Build only inter-cube, not the entire Ternary repo
The existing install.sh runs cargo build --release which builds everything (10–20 min, hundreds of crates). The generated script must override this:

cd ~/PlenumNET && cargo build --release --package inter-cube
This builds only the inter-cube daemon and its direct deps. Much faster.

Issue 3 — Verify Cargo path resolution for inter-cube git dep
inter-cube depends on ternary-math = { path = "../../ternary-math" }. When added as a git dep in YODA's workspace, Cargo resolves this from the repo root of the git checkout — it should work, but must be explicitly tested during sub-task 1. If the path dep fails, the fix is to add ternary-math as a second explicit git dep in YODA's Cargo.toml and use a [patch] section to override:

[patch."https://github.com/SigmaWolf-8/Ternary"]
ternary-math = { git = "https://github.com/SigmaWolf-8/Ternary" }
Issue 4 — OS-specific IP detection (hostname -I doesn't exist on macOS)
The bash script must detect OS and use the right command:

if [[ "$(uname -s)" == "Darwin" ]]; then
  LOCAL_IP=$(ipconfig getifaddr en0 2>/dev/null || ipconfig getifaddr en1 2>/dev/null || echo "0.0.0.0")
else
  LOCAL_IP=$(hostname -I 2>/dev/null | awk '{print $1}' || echo "0.0.0.0")
fi
CUBE_ENDPOINT="${LOCAL_IP}:51820"
Issue 5 — Verification step after tunnel start
After starting the daemon in background, the script must verify the tunnel actually registered before proceeding:

echo "Waiting for tunnel registration..."
REGISTERED=false
for i in $(seq 1 12); do
  sleep 5
  if curl -sf "${CUBE_CRS_URL}/health" > /dev/null 2>&1; then
    echo "✓ Tunnel is live — registered with YODA CRS"
    REGISTERED=true
    break
  fi
  echo "  ... checking ($((i * 5))s)"
done
if [ "$REGISTERED" = false ]; then
  echo "✗ Tunnel did not register within 60s. Check your internet connection and try again."
  exit 1
fi
Issue 6 — Background process persistence (noted as future work)
The daemon is started with & — it dies on terminal close and doesn't survive reboots. This version does NOT install launchd (macOS) or systemd (Linux) services — that is explicitly out of scope for v1. The script must print at the end:

NOTE: The tunnel will stop when this terminal closes.
To reconnect after reboot, re-run:
  CUBE_MODE=cube CUBE_CRS_URL=<YODA_URL> ... ~/PlenumNET/target/release/inter-cube-daemon
Persistent service install (launchd/systemd) is planned for a future version.

Frontend progress indicator
After the user clicks Copy or Download, the modal enters a live "waiting" state that polls YODA until the laptop registers.

Session token binding (how YODA knows which registration is yours)
When the modal opens, it generates a cryptographically random sessionToken (UUID v4) in the browser
The token is embedded in the generated script as an env var: CUBE_SESSION_TOKEN=<uuid>
The laptop's inter-cube-daemon sends the token in the registration body: POST /api/salvi/inter-cube/crs/register with { endpoint, publicKey, sessionToken }
The yoda-crs wrapper intercepts the registration, extracts sessionToken, stores token → {status: registered, address} in an in-memory RwLock<HashMap>, then forwards the stripped request to the inner CRS — zero changes to the inter-cube API
A new endpoint on yoda-crs (port 8081): GET /api/yoda/crs/session/:token
Returns { "status": "pending" } until registration arrives
Returns { "status": "registered", "address": "<13D cube address>" } once the laptop has connected
Frontend state machine in ModelInstallModal
The modal has four states after Copy/Download is clicked:

State	UI shown
waiting	Animated spinner + "Waiting for your server to connect..."
connected	Green ✓ + "Connected — registered as [13D address]" + "You can close this window"
timeout	Warning + "No connection after 10 minutes. Re-run the script and try again."
error	Red banner if polling itself fails (network error)
Polling: GET ${VITE_CRS_URL}/api/yoda/crs/session/${token} every 3 seconds using setInterval. Stops on connected, timeout (after 200 × 3s = 10 min), or modal close.

Script addition for session token
The bash script receives CUBE_SESSION_TOKEN as an additional env var and passes it to the daemon:

CUBE_MODE=cube \
CUBE_CRS_URL="<YODA_URL>" \
CUBE_ENDPOINT="${LOCAL_IP}:51820" \
CUBE_SESSION_TOKEN="<uuid>" \
CUBE_ROLE=inference \
~/PlenumNET/target/release/inter-cube-daemon &
