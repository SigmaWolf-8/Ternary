18 tasks across 3 stages. Here's what the audit uncovered:
Four critical gaps that would stop a CMVP submission cold:

No DRBG (Task A1) — every FIPS 140-3 module requires an SP 800-90A approved random number generator. The femtoclock provides raw entropy, but you need HMAC-DRBG-SHA384 sitting between the noise source and every crypto operation that consumes randomness. Without this, tl_kem, tl_dsa, cipher, x509, and signature are all generating keys from a non-approved source.
No entropy qualification (Task A2) — SP 800-90B requires health tests (repetition count, adaptive proportion) running on every sample from the noise source, plus a vetted conditioning component. Raw femtoclock jitter doesn't qualify without this wrapper.
No Power-On Self-Tests (Task A3) — the 210 KAT vectors in cavp_package.rs are test evidence, not runtime self-tests. FIPS 140-3 requires the module to execute KATs at initialization and refuse all crypto services if any fail. This is the single most-scrutinized requirement during lab evaluation.
No ACVTS JSON format (Task B1) — NIST replaced the legacy .req/.rsp CAVS format with ACVTS JSON in 2020. The current vectors won't be accepted for CAVP certificate issuance.
