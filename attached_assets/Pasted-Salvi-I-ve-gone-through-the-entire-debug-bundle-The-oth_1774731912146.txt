Problem 1 — The WiX Schema Error (the real blocker the error log shows)
The actual WiX compiler errors from the last successful run attempt are:
error WIX0004: The Package element contains an unexpected attribute 'Platform'.
error WIX0004: The Package element contains an unexpected attribute 'Comments'.
These have nothing to do with extension versions. Your product.wxs template uses the WiX v4 schema namespace (http://wixtoolset.org/schemas/v4/wxs) but includes two attributes that don't exist in the WiX v4+ <Package> element:

Platform="{{PLATFORM}}" — In WiX v3, this was on <Product>. In v4+, platform is specified via the -arch flag on the wix build command line. Putting it on <Package> is a schema violation.
Comments="{{DESCRIPTION}}" — Not a valid attribute on <Package>. You already have <SummaryInformation Description="..."> which is the correct v4 way to set this.

Problem 2 — Extension Version Mismatch (the warning that blocks extensions from loading)
The last-run log shows:
WIX6101: Could not find expected package root folder wixext6.
Ensure WixToolset.UI.wixext/7.0.0-rc.2 is compatible with WiX v6.
The machine has WiX CLI v6.0.2, but wix extension add --global WixToolset.UI.wixext (without a version pin) pulls v7.0.0-rc.2 from NuGet. The v7 extension package doesn't contain the wixext6/ folder structure that the v6 CLI expects, so the extension silently fails to register. Then at build time: WIX0144: extension not found.
The report got this part right but its fix is incomplete — it says "pin the version" but doesn't say where in the code.
Problem 3 — Missing -arch argument in wix_build_args()
Even after fixing the template and extensions, the build would still fail. Look at wix_build_args() in wix.rs — it constructs the wix build command but never passes -arch arm64 (or -arch x64). Since you're removing Platform from the template (Problem 1), the architecture now needs to come from the command line. Without it, WiX defaults to x86, which would produce a broken MSI for your ARM64 machine.
