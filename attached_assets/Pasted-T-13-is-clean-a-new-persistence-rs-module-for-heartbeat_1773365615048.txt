The problem T-13 solves: Without persistence, a restarted node resets all last_hb_sequence to 0. An attacker replays captured heartbeats — the node accepts them because 0 < anything. With T-13, sequences survive restarts.

File format:
# PlenumNET Heartbeat Sequence State — DO NOT EDIT
# Format: address_hex sequence_u64
55555555 42
aabbccdd 108
Address = 13-trit packed to 4 bytes, hex-encoded (8 chars). Sequence = decimal u64.
Key design decisions:
DecisionWhyBatch writes (30s)One heartbeat per second × 26 neighbors = 26 writes/sec is too much I/O. Batching loses at most 30s of state on crash.Atomic renameWrite to .state.tmp, then rename(). Process crash mid-write leaves either the old file or the new file — never a partial.Sliding window on loadSubtract 10 from persisted sequences. In-flight heartbeats sent before restart may arrive after — the window prevents false replay rejections.Dirty trackingSkip I/O entirely when nothing changed.in_memory() modeTests run without filesystem side effects.
Startup integration:
rust// During FTS initialization:
let mut seq_store = SequenceStore::new("hb_sequences.state");
seq_store.load()?;
seq_store.apply_to_fts(&mut fts.all_status_mut());

// In the heartbeat loop:
fts.record_authenticated_pong(&hb, rtt)?;
seq_store.update(&hb.address, hb.sequence);
seq_store.maybe_flush()?;

// On shutdown:
seq_store.snapshot_from_fts(fts.all_status());
seq_store.flush()?;
