# PlenumNET Front-End Marketing Audit
## Comprehensive Review & Phased Implementation Checklist

**Prepared for:** Salvi — Applied Physics Division, Capomastro Holdings Ltd.
**Audit Target:** https://PlenumNET.replit.app (marketing front-end for https://github.com/SigmaWolf-8/Ternary)
**Date:** February 12, 2026
**Methodology:** UPIID V1.1 — Critical Analysis & Constructive Creation

---

## EXECUTIVE SUMMARY

The PlenumNET Replit app has a **strong technical foundation** — 1,238-line landing page with motion animations, 15 routed pages, 70+ live API endpoints, authentication, admin dashboard, and a well-structured React/TypeScript codebase with comprehensive test coverage attributes (`data-testid` on every interactive element). The underlying product — a post-quantum ternary computing platform — is genuinely differentiated and technically impressive.

However, the front-end is currently built as an **engineering dashboard wearing a marketing hat**. The audit identifies **47 discrete issues** across brand identity, UX/navigation, SEO, accessibility, performance, conversion optimization, trust signals, and code quality. These are organized below into 5 implementation phases (0-4) from critical fixes to strategic enhancements.

**Key Metrics from Audit:**
- Brand names used inconsistently: 4 (Salvi, PlenumNET, Salvi Framework, Capomastro)
- Dead links in footer: 6 (`#` hrefs)
- Accessibility violations found: 0 aria-labels on landing page, 0 alt text, 0 skip-nav
- React Rules of Hooks violations: 1 (useRef inside `.map()` at landing.tsx:285)
- Pages eagerly imported (no code splitting): 15
- Analytics integrations: 0
- Error boundaries: 0
- OG/Twitter meta tags present: partial (missing og:image, og:url, all twitter tags)
- `prefers-reduced-motion` handling: none
- Dark mode toggle: none (despite `next-themes` being installed)
- Public assets beyond favicon: 0 (no robots.txt, sitemap.xml, og-image, apple-touch-icon)

## COMBINED FINDINGS — FIRST & SECOND PASS

### A. BRAND IDENTITY & MESSAGING

**A1. Brand Name Fragmentation**
Four different names compete for the visitor's attention: the `<title>` tag says "Salvi", the hero says "Ternary Computing Platform", the header bar says "PlenumNET", the GitHub repo is "Salvi Framework", and the footer copyright is "Capomastro Holdings Ltd." A prospect hitting this page cannot form a single mental model of what they're looking at. Establish and enforce a clear hierarchy: **PlenumNET** = product name, **Salvi Framework** = underlying technology, **Capomastro Holdings** = parent company.

**A2. Meta Description Conflicts with Page Content**
The `og:description` meta tag claims "12.7% efficiency gain" while the landing page prominently features "59% information density advantage." These are different metrics but a visitor encountering both will see a contradiction. Unify the headline number.

**A3. Package Name is Generic**
`package.json` declares the project name as `"rest-express"` — a Replit template default. This leaks into build tools, error messages, and dev tooling. Should be `"plenumnet"` or `"salvi-framework"`.

**A4. 404 Page Exposes Developer Language**
The not-found page (`not-found.tsx`) displays: "Did you forget to add the page to the router?" This is a developer-facing message that should never reach end users. Replace with a professional 404 with navigation back to the landing page.

### B. UX & NAVIGATION

**B1. No Top Navigation Bar**
The landing page relies exclusively on a collapsed sidebar as navigation. This is a dashboard/internal-tool pattern, not a marketing site pattern. First-time visitors have no visible way to navigate sections without scrolling the entire page. A sticky top nav with anchor links (Platform | Architecture | Performance | Markets | Docs | Early Access) is essential.

**B2. Sidebar is Wrong Pattern for Marketing**
The sidebar (app-sidebar.tsx) groups 13 navigation items across 3 categories (Explore, Technology, Resources) plus admin tools. This is excellent for the developer dashboard but overwhelming and confusing as the first navigation a marketing visitor encounters. The sidebar should only appear after the user enters the app/tool sections.

**B3. Mobile Navigation Gap**
On mobile, the sidebar collapses to a hamburger trigger in a thin 48px header. For marketing, the landing page should use a standard mobile pattern: sticky header with hamburger → full-screen mobile menu overlay with clear CTAs.

**B4. Too Many Sections — Funnel Unfocused**
Eight major sections before the footer: Hero → Platform → Architecture → Components → Performance → Calendar Preview → Target Markets → Developer CTA. The visitor journey should follow: Problem → Solution → Proof → Trust → CTA. The Calendar Preview section (13-Moon Harmonic Calendar, Fibonacci moon splits) is brilliant IP but will confuse enterprise fintech prospects seeking timing compliance info. Move it to a dedicated sub-page.

**B5. Section Redundancy**
PlatformSection and ComponentsSection present overlapping information about the same 6 capabilities — once as overview cards and again as detailed cards. Merge these into a single, stronger section.

### C. HERO SECTION

**C1. No Visual Element**
The hero is entirely text-based: badges + headline + paragraph + email form + buttons + stats. For a platform claiming "world's first" status, there must be a hero visual — an architecture diagram, network visualization, animated compression demo, or at minimum a product screenshot/mockup.

**C2. Email Capture Too Aggressive Above the Fold**
The email signup form appears before the visitor has any reason to trust or understand the product. Move the email capture below the fold (after establishing credibility) or make it visually secondary to the "View Source" and "Live Demo" action buttons.

**C3. Stats Row Lacks Context**
The hero stats (+59%, 1,011, 80/80, 35) are meaningless without comparison context. "+59%" compared to what? "80/80" of what? Add micro-labels that create instant understanding: "+59% vs Binary", "1,011 Tests Green", "80/80 Roadmap Milestones", "35 VM Opcodes".

### D. CONVERSION & CTA OPTIMIZATION

**D1. Duplicate CTAs with Identical Copy**
Two nearly identical email capture forms ("Get Early Access") in hero and DeveloperCTA sections. The bottom adds a name field but is otherwise a clone. Differentiate: hero CTA should be lightweight ("Join the waitlist"), bottom should be high-commitment ("Apply for SDK Access" with company name, role, use case fields).

**D2. No "Book a Demo" Path**
Enterprise prospects — the financial services, defense, and telecom verticals prominently featured — need a human conversation path, not just an email waitlist. Add a "Book a Demo" or "Talk to Our Team" CTA.

**D3. Social Proof Completely Absent**
Zero testimonials, zero partner logos, zero press mentions, zero advisory board names, zero GitHub stars social proof. The repo has 1 star and 0 forks — linking to it prominently in three places actually hurts credibility. Lead with technical proof (live demo, test results) rather than GitHub vanity metrics until traction exists.

**D4. Comparison Table Has No Trade-offs**
Every row in PerformanceSection shows ternary winning with zero trade-offs acknowledged. This reads as marketing, not engineering credibility. Add at least one honest row (e.g., "Native Hardware: Ubiquitous → Emulated via Binary-Ternary Gateway"). Sophisticated prospects trust transparency.

### E. SEO & TECHNICAL METADATA

**E1. Missing OG Image**
No `og:image` meta tag. Every social share of PlenumNET.replit.app shows a blank preview card. This is the single highest-impact SEO fix — create a 1200×630px branded image.

**E2. Missing Twitter Card Tags**
No `twitter:card`, `twitter:title`, `twitter:description`, `twitter:image`. Twitter/X shares have no formatted preview.

**E3. No Canonical URL**
No `<link rel="canonical">`. Search engines may index multiple URL variants.

**E4. No JSON-LD Structured Data**
No Organization, SoftwareApplication, or WebSite schema markup. Missed opportunity for rich search results.

**E5. No robots.txt**
No `robots.txt` file in the public directory. Search engines have no crawl guidance.

**E6. No sitemap.xml**
No `sitemap.xml` for the 15 routed pages. Search engines can't efficiently discover all content.

**E7. No Dynamic Meta Tags Per Page**
No `react-helmet` or equivalent. Every page serves the same title/description regardless of route. The whitepaper page, API demo, compliance page — all show "Salvi | Deployable Post-Quantum Internet Solutions" as the browser tab title.

**E8. Public Assets Directory is Bare**
The `/client/public/` directory contains only `favicon.png`. Missing: `apple-touch-icon.png`, multiple favicon sizes (16, 32, 192, 512), `manifest.json`, `browserconfig.xml`.

### F. ACCESSIBILITY

**F1. Zero ARIA Labels on Landing Page**
The entire 1,238-line landing page has zero `aria-label`, `aria-labelledby`, `aria-describedby`, `role`, or `alt` attributes. Every icon-only button, every stat, every comparison table row is invisible to screen readers.

**F2. No Skip Navigation Link**
No "Skip to main content" link for keyboard users. The sidebar + header navigation forces keyboard users to tab through many elements before reaching page content.

**F3. No `prefers-reduced-motion` Handling**
Every section uses `framer-motion` animations with staggered delays. Users with vestibular disorders or motion sensitivity preferences are ignored. The hero alone has 8 animation stages from 0s to 0.7s delay.

**F4. Color Contrast Not Verified**
The `text-muted-foreground` color against various backgrounds (especially on cards with `bg-card/70 backdrop-blur-sm`) has not been verified against WCAG AA (4.5:1 text) or AAA (7:1 text) contrast ratios.

**F5. Form Labels Missing**
The hero email input and developer signup form rely on `placeholder` text as the only label. Placeholders disappear on focus and are not reliable labels for accessibility.

### G. VISUAL DESIGN & THEME

**G1. Light/Dark Mode Brand Color Mismatch**
Light mode uses blue primary (`hsl(210 100% 45%)` — a professional blue). Dark mode uses orange-red primary (`hsl(9 75% 61%)` — a warm coral/rust). These are completely different brand identities. A visitor switching between modes will think they've landed on a different product. Unify the brand color across both themes.

**G2. Dark Mode Toggle Missing**
`next-themes` is installed as a dependency but the `ThemeProvider` is never wired into `App.tsx` and there is no user-facing toggle anywhere. The site relies entirely on system preference. Developer audiences expect a manual toggle.

**G3. Font Loading Strategy**
Only Inter is loaded via Google Fonts. The CSS declares `'Inter', 'Poppins', sans-serif` as the font stack but Poppins is never loaded — it's a phantom fallback that will never render. Either load Poppins or remove it from the stack. The document standard (Felix Titling headers / Century Gothic body) is not reflected in the web app.

**G4. No Hero Visual / Product Screenshot**
Reiterated from C1 — the entire above-the-fold experience is text-only. There is no visual representation of what the product looks like or does.

### H. CODE QUALITY & PERFORMANCE

**H1. React Rules of Hooks Violation**
`landing.tsx` line 285-286: `useRef()` and `useInView()` are called inside a `.map()` callback within `PlatformSection`. This violates React's Rules of Hooks. It works coincidentally because the array length is static, but it will break if the array becomes dynamic and will cause issues with React strict mode and future React versions. Extract to a separate component.

**H2. Zero Code Splitting**
All 15 pages are eagerly imported in `App.tsx`. Pages like `api-demo.tsx` (60KB), `ternarydb.tsx` (70KB), `github-manager.tsx` (54KB), `calendar.tsx` (46KB) are all bundled and loaded upfront even when the user only visits the landing page. Use `React.lazy()` + `Suspense` for route-level code splitting.

**H3. No Error Boundary**
No `ErrorBoundary` component exists anywhere in the app. A runtime error in any child component will crash the entire application with a white screen.

**H4. No Analytics**
Zero analytics integration — no Google Analytics, Plausible, Umami, PostHog, or Mixpanel. There is no way to measure traffic, conversion rates, or user behavior. This makes all marketing decisions blind.

**H5. Animation Performance Budget**
Framer Motion staggered animations on every section create a "loading in" feel on slower connections. The hero has 8 animation stages. Reduce animation on mobile, respect `prefers-reduced-motion`, and tighten stagger delays.

**H6. No Service Worker / PWA**
No service worker, no web app manifest, no offline capability. Low priority for a marketing site but expected for a technology platform demo.

### I. CONTENT & FOOTER

**I1. Six Dead Footer Links**
Company section links (About, Blog, Careers, Contact) all point to `"#"`. Social icons (Twitter, LinkedIn) also point to `"#"`. Dead links on a production page signal "not ready for business."

**I2. No Developer Quick-Start Code Snippet**
For a platform with 70+ API endpoints, there is no code example on the landing page showing integration simplicity. A `curl` or `npm install` example instantly communicates "production-ready and usable today" better than any badge.

**I3. Legal Pages Render as `<pre>` Blocks**
The legal page (`legal.tsx` line 74-79) renders document content inside a `<pre>` tag with `whitespace-pre-wrap`. This produces raw, unformatted text blocks rather than properly structured legal documents. These pages represent the company legally and should use proper heading/paragraph formatting.

**I4. Whitepaper Uses Custom Markdown Parser**
The whitepaper page (`whitepaper.tsx`) implements a regex-based markdown-to-HTML parser (lines 46-72). This is fragile and incomplete — it will break on edge cases. Use a proper library like `marked` or `react-markdown`.
