#### TASK A1: XMSS Merkle Tree Extension
**File:** `crypto/signature.rs` (extend existing)
**Priority:** P0-CRITICAL — closes last algorithm gap
**Effort:** ~200-300 lines added to signature.rs

**What exists:** Lamport OTS with `KeyChain` for sequential multi-message signing. This is the foundational primitive but NOT full XMSS.

**What to build:**
```
1. WOTS+ (Winternitz One-Time Signature Plus)
   - Parameterized Winternitz parameter w (typically w=16)
   - WOTS+ key generation from seed + address
   - WOTS+ sign: chain hash with configurable w
   - WOTS+ verify: reconstruct public key from signature
   - Use existing hash.rs/sha2.rs for internal hashing

2. Merkle Tree Construction
   - Binary tree of height H (H=10 → 1024 signatures, H=20 → 1M)
   - L-tree for compressing WOTS+ public key
   - Tree hash algorithm per SP 800-208 Section 4.1.5
   - Root node = XMSS public key

3. XMSS Sign/Verify
   - Sign: pick leaf index → WOTS+ sign → auth path
   - Verify: recompute root from signature + auth path
   - Index = monotonic counter (CRITICAL: reuse = compromise)

4. State Management
   - XmssState struct: { secret_seed, index: u32, tree_height: u8 }
   - increment_index() — panics/returns error if exhausted
   - Serialization for PlenumDB persistence
   - MUST NOT allow index reuse across restarts

5. Parameter Sets (per CNSA 2.0)
   - XMSS-SHA2_10_256: H=10, n=32, w=16, SHA-256
   - XMSS-SHA2_16_256: H=16, n=32, w=16, SHA-256
   - XMSS-SHA2_20_256: H=20, n=32, w=16, SHA-256
   - Do NOT implement XMSSMT (multi-tree) — prohibited by CNSA 2.0
```

**Tests to add:**
- WOTS+ sign/verify round-trip for each w value
- Merkle tree: generate tree, verify auth path for every leaf (small H=4 test tree)
- Index exhaustion: verify panic/error when tree is fully used
- State serialization round-trip
- SP 800-208 test vectors (if available in cavp_package.rs, extend there)

**Acceptance:** Full XMSS construction with stateful index management. `signature.rs` exports `XmssKeypair`, `xmss_sign()`, `xmss_verify()`, `XmssState`.

#### TASK A3: Firmware Signing Pipeline
**File:** NEW `crypto/firmware_sign.rs`
**Priority:** P1-HIGH — NSA most urgent mandate (2025 prefer, 2030 exclusive)
**Effort:** ~150 lines

**What to build:**
```
1. FirmwareSignature struct
   - algorithm: enum { Lms, Xmss, DualSign }
   - signature_bytes: Vec<u8> / [u8; N]
   - signer_id: [u8; 32]
   - timestamp: u64 (femtosecond from drivers/femtoclock.rs)

2. sign_firmware(image: &[u8], key: &SigningKey, algo: SignAlgo) -> FirmwareSignature
   - Hash image with SHA-256 (LMS/XMSS use SHA-256 internally)

3. verify_firmware(image: &[u8], sig: &FirmwareSignature, pk: &VerifyKey) -> bool

   - Verify signature
   - For dual-sign: both must pass

4. Integration point with arch/boot.rs
   - verify_boot_image() called from boot sequence
   - Reject tampered images
   - Log verification result with timestamp
```

**Tests:** sign/verify round-trip, tamper detection (flip bit → reject), dual-sign mode, timestamp presence.

**Register in:** `crypto/mod.rs` and update `cnsa2.rs` compliance tracker.
