T-21: deregistration.rs — 494 lines, 14 tests
Prevents unauthorized removal of registrations.
Domain Separation
Registration:     "PlenumNET-CRS-REG-v1"   ‖ addr ‖ endpoint ‖ pk ‖ kem ‖ ts
Deregistration:   "PlenumNET-CRS-DEREG-v1"  ‖ addr ‖ ts ‖ reason
Different domain = a registration signature cannot be replayed as a deregistration and vice versa. The reason byte is part of the signed message — an attacker who captures the signature can't change the reason after the fact.
Deregistration Reasons
ReasonCodeEffectGraceful0x01Normal shutdown, address enters grace periodMaintenance0x02Temporary, expected to re-registerKeyCompromise0x03Emergency — triggers alerts to all neighborsMigration0x04Moving to new address, old address released
Verification Flow
verify_deregistration(dereg, registration_pk, registration_ts, now_fs):
  1. Timestamp within 30s window?             → StaleTimestamp
  2. Timestamp > registration timestamp?      → ReplayDetected
  3. Public key matches registration's pk?    → KeyMismatch
  4. TL-DSA-87 signature valid?               → InvalidSignature
  5. Return Ok(reason)

```
#### Entropy — Base-3 Information Measure
```
H₃ = -Σ p_i × log₃(p_i)

Perfectly balanced (1/3, 1/3, 1/3): H₃ = 1.0
All on one value (1, 0, 0):         H₃ = 0.0
Using log₃ (not log₂) so the max is exactly 1.0 for 3 equiprobable values.
Hotspot / Cold Spot Detection
A hotspot is a dimension where one trit value holds >60% of registrations. This means placement is imbalanced — the allocator should avoid adding more nodes with that value in that dimension.
A cold spot is a dimension-value pair with zero registrations. The recommended_values() function returns the least-populated value for each dimension — ideal for constructing a maximally-sparse candidate address.
Imbalance History
Tracks (registration_count, global_imbalance) over time. If the allocator (T-16) is working correctly, imbalance should stay flat or decrease as registrations grow. A rising trend indicates the allocator is failing to spread nodes.
