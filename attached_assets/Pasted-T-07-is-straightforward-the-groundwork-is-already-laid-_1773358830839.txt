The verification flow:
CRS response arrives with (endpoint, public_key, reg_signature, kem_pk, timestamp_fs)
    │
    ▼
resolve_neighbor_verified()
    │
    ├─ signature missing?  → ForgeryAlert(SignatureMissing), neighbor stays Unknown
    ├─ public_key empty?   → ForgeryAlert(PublicKeyMissing), neighbor stays Unknown
    │
    ├─ Reconstruct canonical message via build_registration_message()
    │   (same function the signer used in T-06)
    │
    ├─ tl_dsa::verify(public_key, canonical_msg, signature, TlDsa87)
    │   ├─ false → ForgeryAlert(SignatureInvalid), neighbor stays Unknown
    │   └─ true  → endpoint + pk + sig stored, signature_verified = true, → Connecting
    │
    └─ Result: Ok(true) / Ok(false) / Err(ForgeryAlert)
Key security property: A compromised CRS cannot redirect tunnels. It can return a record with a forged endpoint, but it cannot forge the TL-DSA signature because it doesn't hold the registrant's secret key. The worst case is denial of service (refusing to return records).
