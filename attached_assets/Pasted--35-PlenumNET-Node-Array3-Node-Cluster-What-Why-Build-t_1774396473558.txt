Rep C and GF(3) — The Dual Representation
GF(3) {0, 1, 2} — internal computation. Used in the port formula and offset calculations. Rep C {1, 2, 3} — wire format. Conversion: rep_c = gf3 + 1, gf3 = rep_c - 1.

Zero is structurally impossible in Rep C. Its presence in any trit of any address at any trust boundary is mathematical proof of forgery, detectable in constant time with no branching on secrets.

Dimension	GF(3)	Rep C	Meaning
Plane (trit 2)	0, 1, 2	1, 2, 3	Security domain (Data, Control, Management)
Role (trit 1)	0, 1, 2	1, 2, 3	Functional class (Primary, Secondary, Tertiary)
Instance (trit 0)	0, 1, 2	1, 2, 3	Service variant
Port Formula
port = BASE_PORT + (node × 27) + (plane × 9) + (role × 3) + instance
Where BASE_PORT = 11111, all positional values GF(3) {0, 1, 2}. The node is a multiplier selecting which of the 3 nodes owns this port range — NOT a 4th cube dimension. The cube stays 3D (plane, role, instance). Single node = node 0, no peers.

Array3 (§3.5) — 81 slots across 3 nodes:

Node	node_id (GF(3))	Port Range	(2,2,2) Slot Port
Node 1	0	11111–11137	11124 — THE GATEWAY (cluster-singular)
Node 2	1	11138–11164	11151 — regular slot (routes through Node 1 gateway)
Node 3	2	11165–11191	11178 — regular slot (routes through Node 1 gateway)
ONE gateway for the entire Array3 cluster. Only Node 1's (2,2,2) slot at port 11124 is the gateway. This is the single outbound security chokepoint — it punches ONE clean hole through the firewall. All 81 slots across all 3 nodes funnel outbound through Node 1's gateway. Nodes 2 and 3 still have a (2,2,2) slot in their port range, but it is NOT a gateway — it is a regular service slot that routes outbound through Node 1:11124.

Firewall rule: open port 11124 inbound/outbound on Node 1's IP. That's it. No other ports need firewall exposure. Internal LAN traffic between nodes uses the full 81-port range freely — the firewall only governs the edge.

27→3 Projection (§9)
The projection is source-agnostic per spec §9.3 — takes 27 trits from ANY source (internet TDNS, LAN entity scan, manual entry, future methods) and returns 3 trits.

27 dimensions partition into three groups of 9 (27 = 3² + 3² + 3²). Each group determines one port trit via project_to_gf3(k, 9) with polarity-adjusted dimensions.

For each port trit: take 9 dimensions, apply polarity (invert if −), count k = polarity-adjusted dimensions with value 3, apply project_to_gf3(k, 9) = min(floor(k/3), 2) + 1.

Polarity tables:

Plane group (security domain): D1, D2(−), D3, D9(−), D10, D17, D19, D25, D26
Role group (functional class): D5, D6, D7, D8, D12, D18, D22(−), D23, D24(−)
Instance group (temporal/scale): D4, D11, D13, D14, D15, D16, D20, D21, D27
Dimensions marked (−) are polarity-inverted before aggregation: if value is 1→3, if 3→1, if 2→2. Polarity is a structural property of the schema, not a tuning parameter.

D19 (PolicyPresence) in Plane: compliance posture is a security domain property. D8 (Intelligence) in Role: what kind of processing. D20 (CostModel) in Instance with + polarity: subscription implies higher availability. D27 (Confidence) in Instance to balance 9/9/9 partition.

Zero-Sentinel Pre-Filter
At every trust boundary (multiplexing header, caller identity, capability token fields, routing messages, redirect entries): if ANY trit in a Rep C address is 0, reject immediately before any cryptographic operation. Rep C values are {1, 2, 3} — zero is structurally impossible and its presence is proof of forgery.

Array3 Formation Protocol
Node boots with CUBE_NODE_ID=N (env var, default 0) and CUBE_ARRAY3_PEERS=ip1:port,ip2:port
Node binds its 27-port range: BASE_PORT + (N × 27) through BASE_PORT + (N × 27) + 26
Node 0 (CUBE_NODE_ID=0) is always the cluster gateway — its (2,2,2) slot at port 11124 is the single outbound security chokepoint that punches through the firewall
Nodes 1 and 2 route all outbound traffic through Node 0's gateway at :11124 — their (2,2,2) slots are regular service slots, NOT gateways
Node connects to each peer via existing CUBE_PEER_PORT infrastructure
First handshake includes: node_id, wire protocol version, port range, slot inventory, daemon version, gateway_address (Node 0 advertises itself as gateway)
Peer validates: no node_id collision (reject duplicate), wire protocol compatible (V3 accepts V2 during dual-acceptance), port ranges don't overlap
On success: peer mesh formed, slot-to-node routing populated, outbound routing through Node 0 gateway confirmed, failover candidates identified
Single node = CUBE_NODE_ID=0, no peers, ports 11111–11137, gateway at :11124. Adding a second node later requires no reconfiguration of node 0 — new nodes auto-discover the gateway.

Firewall posture: One port open on one IP. All 81 internal service ports are LAN-only. The gateway multiplexes outbound through :11124 via TLS. This is by design — a clean single-hole firewall punch.

Slot-to-Node Routing
The 3-trit slot address (plane, role, instance) maps to offset 0–26 within EACH node's 27-slot range. The CRS tracks slot→node ownership. Two services with identical classifications on different nodes occupy the "same slot" on different nodes — this IS the HA replica mechanism. The CRS routes to the primary; on failure, traffic fails over to the replica.
