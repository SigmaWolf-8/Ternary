## 3. Definitions Glossary

### 3.1 Infrastructure Terms

**Active Directory (AD)**
Microsoft's identity and access management service for Windows networks. Provides
authentication (Kerberos/NTLM), group policy enforcement, and user/group management.
Replaced in PlenumNET by TDNS v2.5 + TL-DSA identity layer.

**CAL (Client Access License)**
Microsoft's per-user or per-device licensing model for accessing Windows Server services.
In PCIQ3863-02: 10 RDS CALs ($2,690) and 25 User CALs ($1,775). These have zero
equivalent in PlenumNET — TDNS addresses replace per-seat licensing entirely.

**RDS (Remote Desktop Services)**
Windows Server role that enables remote GUI access to server resources. Replaced in
PlenumNET by the Kong Konnect web portal (293 endpoints, TL-DSA authenticated sessions).

**DNS (Domain Name System)**
The internet's naming infrastructure — maps human-readable names to IP addresses.
Replaced in PlenumNET by TDNS v2.5, which simultaneously serves as resolver, identity
system, routing protocol, and structural forgery detection system.

**SMB/CIFS (Server Message Block / Common Internet File System)**
The Windows and Samba network file-sharing protocol used for drive mapping and UNC path
resolution (e.g., `\\server\share`). In a PlenumNET deployment, SMB/CIFS shares are
served by Samba on Ubuntu (transition) or by the PlenumNET native filesystem service
(bare-metal target), with access governed by TDNS address-bound TL-DSA key policies.
**Not to be confused with SME (Small-to-Medium Enterprise).**

**Group Policy / GPO**
Windows mechanism for centrally managing desktop and server configuration across a domain.
Drive maps, security policies, software deployment — all governed by GPOs stored in
SYSVOL. Replaced in PlenumNET by Address-Bound TL-DSA key policies, where access rules
are cryptographically bound to topology rather than stored in a mutable policy database.

**VM Migration**
Moving virtual machines from one host server to another — the primary labour item in
line 7. Replaced in PlenumNET by Inter-Cube GLB/CON automated workload distribution
across hypercube nodes.

**SME (Small-to-Medium Enterprise)**
The target market category for the Strategy C managed infrastructure offering: Canadian
businesses with 10–250 employees facing 3–5 year server refresh cycles and recurring
Microsoft licensing costs. The Salvi Homes deployment is the reference case.

### 3.2 PlenumNET / Salvi Framework Terms

**TL-DSA (Ternary Lattice Digital Signature Algorithm)**
PlenumNET's post-quantum digital signature scheme. Security levels: 44 / 65 / 87.

**TL-KEM (Ternary Lattice Key Encapsulation Mechanism)**
PlenumNET's post-quantum key encapsulation. Security levels: 512 / 768 / 1024. Provides
quantum-resistant key agreement without any classical DH/ECDH protocol.

**TIS-27 (Ternary Identity Sponge — 27 dimensions)**
PlenumNET's sole cryptographic hash primitive. Performance: 191 ns/hash, 2.52 GB/s.
State: 54 trits. Rate: 27 trits. Capacity: 27 trits. Rounds: 27. Stride: 13

**TLSponge-385**
The high-performance variant of the TIS-27 sponge construction optimized for bulk data
operations. Performance: ~10 MB/s via AVX2/NEON SIMD, bulk squeeze, and rayon
parallelism. The hash core for TM-2026-011 (T-AE-MAC / Dual-Phase Authenticated

**TDNS v2.5 (Ternary Domain Name System)**

The external wire representation of ternary values. Digits: {1, 2, 3}. Zero is never a

**Rep A / Rep B**

**GF(3) (Galois Field of Order 3)**

### A.8 Automated Key Rotation — Full Round-Trip

> **Status: Functional.** The topology-derived key architecture means rotation is
> mathematically inherent to the system design — not a scheduled maintenance event.
> The automation layer described below orchestrates existing functional primitives into
> a continuous, observable, zero-operator-intervention lifecycle.

---

#### A.8.1 Why Key Rotation Is Automatic by Design

PlenumNET's tunnel key derivation formula is:

```
key = TIS-27( context="PlenumNET-CON-v2.5" || addr_local || addr_remote || shared_secret )
```

Because the key is deterministically derived from the topological adjacency of the two
endpoint addresses:

1. **Any topology change** (new node registration, address re-provisioning, tunnel
   teardown/re-establishment) **causes both endpoints to independently and simultaneously
   compute a new key** using the identical derivation function.
2. **No key exchange protocol is needed.** Both sides arrive at the same new key without
   communicating it.
3. **The previous key is immediately invalid** at both endpoints the moment the topology
   state changes. There is no window during which the old key is valid on one side but
   not the other.

This is a mathematical consequence of the geometry — not a policy. It cannot be disabled.

---

#### A.8.2 Key Classes and Their Rotation Mechanisms

| Key Class | Rotation Trigger | Rotation Mechanism | Operator Action Required |
|---|---|---|---|
| **Inter-Cube tunnel keys** (26 per node) | Topology event (node join/leave, address change, scheduled rotation cycle) | Automatic TIS-27 re-derivation by both endpoints simultaneously | None |
| **Node TL-DSA keypair** | Scheduled policy rotation or compromise event | Automated rotation daemon issues new keygen, re-signs CRS registration, propagates new public key via TDNS, retires old key | Monitor only |
| **User TL-DSA keypairs** | Scheduled policy rotation or user lifecycle event | Automated rotation daemon via onboarding service; new key issued, old key revoked in TDNS | Monitor only |
| **HPTP clock keys** | Coprime rotation step (built into coprime_clock_rotation.rs) | Automatic clock source failover per generator theorem; new measurement chain established | None |
| **TPM-bound capability keys** | Firmware/hardware change event (PCR mismatch) | Re-binding triggered automatically on next boot; new PCR baseline recorded | Review alert |
| **Heartbeat MACs** | Per-heartbeat (every 30 seconds) | Each heartbeat carries a fresh TIS-27 MAC derived from current key + sequence number | None |
