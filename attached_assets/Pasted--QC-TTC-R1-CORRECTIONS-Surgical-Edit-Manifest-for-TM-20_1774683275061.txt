## EDIT E-04: §3.7.1 — Fix Distance Quantization (Lossless Round-Trip)

**R1 Finding:** #3 (PlenumNET, CRITICAL) — Distance quantization is lossy; LZ77 requires exact distances.

**Location:** §3.7.1, the "Distance quantization" block

**Find:**
```
**Distance quantization:**
\```
bucket = floor(matchDist / (windowSize / 256))  clamped [0,255]
symbol = 767 + bucket
// decode: matchDist = bucket × (windowSize/256) + (windowSize/512)
\```
```

**Replace with:**
```
**Distance quantization (lossless):**
\```
bucket_size  = windowSize / 256
bucket       = floor(matchDist / bucket_size)  clamped [0,255]
intra_offset = matchDist - (bucket × bucket_size)
symbol       = 767 + bucket

// Encoding: emit bucket as ANS symbol, then emit intra_offset as
// fixed-width binary immediately after the symbol in the trit stream.
// Bit width = ceil(log₂(bucket_size)).
// For TTC2-2 (windowSize=243 KB=248,832 bytes): bucket_size=972, bits=10.
// For TTC3-3 (windowSize=19,683 KB=20,155,392 bytes): bucket_size=78,732, bits=17.

// Decoding:
bits_needed = ceil(log₂(windowSize / 256))
matchDist   = bucket × bucket_size + read_bits(bits_needed)
\```

**Rationale (QC-TTC-R1 Finding #3):** The v2.0 decode formula `bucket × (windowSize/256) + (windowSize/512)` reconstructed the bucket center, not the exact distance. LZ77 decompression (§4.10) requires byte-exact distances. The intra-bucket offset preserves exact distances while retaining the entropy benefit of ANS-coding the coarse bucket distribution.
```

#### 9.1.1 TL-DSA Signature Appendix

The full TL-DSA signature is appended after the last chunk payload in the archive. PQC signatures (TL-DSA at NIST Security Level 5) are typically 2–4 KB — too large for inline header storage.

**Archive layout with signature:**
\```
[112 bytes: TTC1 header]
[N × 16 bytes: chunk map]
[chunk payloads...]
