Fix Installer Script Encoding Errors
What & Why
Both the Array3 Deployer (deploy-yoda.ps1) and the MSI Installer (install-plenumnet-msi.ps1) fail to parse on Windows because of Unicode characters in executable lines. When Invoke-WebRequest downloads a UTF-8 script, em dashes (—) get mangled into â€" on systems using Windows PowerShell 5.1 with non-UTF-8 default encoding, causing cascading parse errors. The deployer also has an unescaped > on line 656 that PowerShell interprets as a stream redirection operator.

Done looks like
Both installers download and run without parse errors on Windows 10/11 with default encoding settings
No Unicode characters appear in any executable (non-comment) lines of either script
Both scripts include a UTF-8 BOM so Windows PowerShell 5.1 detects the encoding correctly
The .bat launchers for both scripts continue to work as before
Out of scope
Functional changes to what the installers do
Changes to comment-only lines (box-drawing characters in step banners are fine since PowerShell ignores comments)
Changes to the Unix installer (install.sh) or the legacy .bat installer (those have no non-ASCII characters)
