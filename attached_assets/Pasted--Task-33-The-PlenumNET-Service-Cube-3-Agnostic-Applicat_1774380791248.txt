## 13. TDNS-L → TDNS Promotion: Local to Global

### 13.1 The Two Scopes

TDNS operates at two scopes with the same 54-trit address format:

| Scope | TLD | First 27 trits | Second 27 trits | Example |
|---|---|---|---|---|
| Local (TDNS-L) | `.plm.local` | Ontological classification (27-question scan) | Ternary host identifier (encodes IPv4/IPv6) | `files.salvi-homes.plm.local` |
| Global (TDNS) | `.plm` | Ontological classification (27-question scan) | TL-Sponge-43 identity hash of canonical URL | `files.salvigroup.plm` |

The wire format is identical. The 54 trits are always two halves of 27. The interpretation of the second half depends on the TLD suffix — `.plm.local` means the second half is a ternary host ID (from which IP addresses are derived), `.plm` means the second half is a cryptographic identity anchor. No flag bit, no version field. The TLD IS the mode switch.

### 13.2 What's Preserved, What Changes

When a local service promotes to global:

**Preserved (unchanged):**
- The 27 classification trits (first half) — the service IS the same thing at both scopes
- The TDNS-L slot projection — `project_to_gf3` produces the same 3-trit port address from the same classification
- The 13 capabilities — the cube provides the same stack regardless of scope
- The 9-factor shell — Factor 9 (SignHere) applies identically at both scopes
- The service's TL-DSA identity keypair — same key, same proof of identity
- The CRS registration record — extended with a global address, not replaced

**Recomputed (second 27 trits only):**
- Local: ternary host ID → derived from IPv4/IPv6 via bidirectional bijection (TM-2026-019.2 §6)
- Global: TL-Sponge-43 hash → computed from the canonical global URL

The first half is classification. It doesn't change because the service doesn't change. The second half is binding — local binds to a network position (IP address), global binds to a namespace identity (URL hash). Same service, two bindings, two addresses.

### 13.3 The Promotion Workflow

```
1. Service is registered locally
   Address: [27 classification trits] · [27 ternary host ID trits]
   Resolves: files.salvi-homes.plm.local → 192.168.1.2

2. Operator initiates promotion
   The CRS computes the global second half:
   global_anchor = tl_sponge_43(canonical_url)
   Where canonical_url = "files.salvigroup.plm"

3. Dual registration
   The service now has TWO addresses:
   Local:  [27 classification] · [27 host ID]     → .plm.local (LAN routing)
   Global: [27 classification] · [27 identity hash] → .plm (fabric routing)

4. Both addresses remain live
   LAN clients resolve .plm.local → ternary host ID → IPv4/IPv6 (direct)
   Global clients resolve .plm → identity hash → Inter-Cube fabric routing
   The service processes both — it doesn't know which address the caller used
```

### 13.4 Resolver Behavior

The TDNS-L resolver on the local cube handles both scopes:

**Inbound `.plm.local` query:** Resolve from CRS. Return the ternary host ID, from which IPv4 (A record) and IPv6 (AAAA record) are derived. This is pure local resolution — the query never leaves the site.

**Inbound `.plm` query:** Two cases:
- If the target is a promoted local service: the CRS holds both addresses. Return the global identity hash for fabric routing, OR if the caller is on the same LAN, short-circuit to the local address (why route through the fabric when the service is on the same network?).
- If the target is a remote global service: forward the query to the Inter-Cube fabric via the gateway at (1,1,1). The CON overlay routes to the target site's cube. That site's CRS resolves the global address to a local slot.

**Outbound `.plm` resolution (this site's service accessed from another site):**
The remote site's resolver queries the fabric. The fabric routes to this site's gateway. The gateway routes to the local slot. The 9-factor shell applies at the gateway. The service doesn't know the caller is remote.

### 13.5 The Slot Projection Is Scale-Invariant

The `project_to_gf3` projection uses only the first 27 trits (classification). Since the classification is identical at both scopes, the slot assignment is identical. A file service classified the same way at `.plm.local` and `.plm` gets the same (plane, role, instance) address. Same port. Same position in the cube.

This means: the cube's internal architecture doesn't change when a service promotes. The service keeps its slot. Other services that call it by classification query get the same result. The only thing that changes is the external reachability — the service is now discoverable and routable through the global TDNS fabric, not just the local network.

### 13.6 Multi-Site Resolution Chain


### 13.8 Demotion

A promoted service can be demoted back to local-only by removing its global TDNS entry from the fabric. The local `.plm.local` address remains. The slot doesn't change. The capabilities don't change. The service doesn't know it was demoted. Demotion is a routing change at the fabric level, not an architectural change at the cube level.
