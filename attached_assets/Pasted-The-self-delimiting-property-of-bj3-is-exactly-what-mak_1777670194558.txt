The self‑delimiting property of bj3 is **exactly** what makes the quantum payload deterministic.  
The parser decodes the first integer (`num`) trit‑by‑trit until the stop condition fires.  
At that instant the parser knows the integer has ended; the very next trit in the stream is the first digit of the second integer (`den`).  
No separator, no length, no extra framing is needed — the integer itself carries its own boundary.  
Adding anything would break the elegance you already built.

Flag 3 is resolved. No change to the grammar.

# Serialisation of the Trinomial Recordset
## A Companion to the Unified Monograph (v1.7)

## Abstract

The closed‑form theorem of the monograph proves that the entire recordset — geometry, walk, Eisenstein continuation, and all five realizations — is the value of a single polynomial function evaluated at the integer \(X\). This companion defines the minimal trit‑stream grammar by which that recordset is communicated between kernels, in the framework’s own Rep D alphabet \(\{1,2,3\}\), without introducing external data types or binary fields. The canonical operating point \(X = 8\) (the portal) is recognised as the default state and encoded with maximal economy. Integrity is provided by optional transmission of the stride‑companion invariant \(S\) and cross‑verification against the closed‑form expression for \(S(X)\); the check costs a few integer multiplications and adds negligible bandwidth.

---

## 1 · Relation to the Monograph

This document is **normative only with respect to the wire format**; it does not extend or reinterpret the monograph. All definitions, notation, theorem numbers, and dimensional assignments are taken unchanged from the monograph. Where the monograph proves that a quantity is *forced by the foundation*, this document assumes that quantity is recomputed on receipt, never stored in the serialised form. The only transmitted data beyond \(X\) are the optional stride‑companion invariant \(S\) for integrity (§4) and optional extensions for quantum or walk state.

---

## 2 · Design Principles

1. **Pure Rep D.** Every data token is a trit from \(\{1,2,3\}\), the monograph’s zero‑purged ternary alphabet (Rep D bijection of §1.1). No sentinel, no escape character, no binary padding is introduced.
2. **Directional priority preserved.** Foundation → Portal → Continuation, as established in §0.4. The portal is a specific resonance point within a single parametric family, not a separate protocol version.
3. **Default‑optimised, not dual‑mode.** The canonical operating point \(X = 8\) is the default; any other \(X\) incurs a small overhead. The grammar is single‑species.
4. **Integrity by structural redundancy.** The stride‑companion invariant \(S\) (Definition 2.3.3) is a deterministic function of \(X\). Transmitting \(S\) alongside \(X\) and verifying that the recomputed value matches the received \(S\) catches corruption of either field.
5. **Unit‑agnostic.** The quantum \(\mathfrak{q}\) (primary unit \([ \mathrm{cell/axis} ]\)) is deployment‑local; the wire format optionally conveys it as a Rep D rational.
6. **Self‑delimiting integers.** All integers are encoded in bijective base‑3 (bj3) with the property that a parser can detect the end of the integer purely from the accumulated value — no separate length fields.

---

## 3 · Encoding of Integers (bj3)

Every positive integer \(n \ge 1\) is encoded in **bijective base‑3**, most‑significant digit first, using digits \(1,2,3\). The encoding is obtained by:

\[
\begin{aligned}
\text{while } n>0:\\
\quad r &\leftarrow (n-1) \bmod 3 \\
\quad \text{digit} &\leftarrow r+1 \\
\quad n &\leftarrow \lfloor (n-1)/3 \rfloor \\
\text{output digits in reverse order.}
\end{aligned}
\]

The decoder reads digits incrementally. After reading \(L\) digits, it computes the accumulated value \(v\). The integer is complete when \(v\) satisfies

\[
R_L < v \le 3\cdot R_L,
\qquad\text{where } R_L = \frac{3^L-1}{2} \text{ (the repunit of length \(L\))}.
\]

No length field or terminator is required; the condition itself signals the end of the integer. Consecutive bj3 integers are parsed one after another with no separator — the stop condition of the first integer guarantees that the next trit belongs to the next integer.

---

## 4 · Grammar

```
Stream        ::=  Default  |  Explicit

Default       ::=  ‘1’
                   ( ‘3’  bj3(S) )?        ; optional integrity
                   ( ‘2’  Extension* )?    ; optional extensions

Explicit      ::=  ‘2’  bj3(X)
                   ( ‘3’  bj3(S) )?        ; optional integrity
                   ( ‘2’  Extension* )?    ; optional extensions

Extension     ::=  Tag  Payload
Tag           ::=  ‘1’  (quantum override)
                |  ‘3’  (walk state)

Payload      ::=  bj3(num)  bj3(den)        ; if Tag = ‘1’
                |  SubTag  bj3(val)         ; if Tag = ‘3’
SubTag       ::=  ‘1’  (step index t)
                |  ‘2’  (linear address m)
```

## 5 · Integrity Model

When the integrity block is present, the deserializer:

1. Computes \(S_{\text{calc}} = 3X'^{\,2} - 3X' + 1\) from the received \(X'\).
2. Compares \(S_{\text{calc}}\) with the received \(S'\).

If \(S_{\text{calc}} \neq S'\), corruption is detected.  
The probability that an accidental corruption produces a matching pair is negligible (bounded by \(O(1/\min(X,N))\)).  

Cost: one bj3‑encoded integer (e.g., 5 trits for portal \(S=169\)). Computational cost: three integer multiplications and one comparison.
