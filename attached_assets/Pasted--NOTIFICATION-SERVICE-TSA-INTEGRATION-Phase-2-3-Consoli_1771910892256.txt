## BEFORE vs AFTER (At a Glance)

| Header | Phase 1 (Legacy) | Phase 2 (Migration) | Phase 3 (TSA Primary) |
|--------|-------------------|---------------------|----------------------|
| `X-PlenumNET-HPTP-Timestamp` | Raw HPTP string | Still sent (fallback) | Removed |
| `X-PlenumNET-Message-Hash` | SHA-3 hex | Still sent (fallback) | Removed |
| `X-PlenumNET-TLDSA-Signature` | TL-DSA sig | Still sent (fallback) | Removed |
| `X-PlenumNET-TSA-Token` | — | Base64 RFC 3161 TST | Only proof header |
| `X-PlenumNET-TSA-Serial` | — | Added (traceability) | Kept |
| `X-PlenumNET-TSA-GenTime` | — | Added (quick parse) | Kept |
| `X-PlenumNET-TSA-Policy` | — | Added (tier visibility) | Kept |
| `X-PlenumNET-TSA-Merkle` | — | Added (audit linkage) | Kept |
| `X-PlenumNET-Proof-Mode` | — | `tsa+legacy` | `tsa-only` / `none` |

**Verification:** Any RFC 3161 tool (OpenSSL, Adobe, jarsigner) verifies the TST offline — no PlenumNET dependency.

## PHASE STRATEGY

| Phase | Headers Sent | TSA Failure Behavior | Rollback | When to Advance |
|-------|-------------|---------------------|----------|-----------------|
| **2** (default) | Legacy + TSA (additive) | Fall back to legacy headers | Remove TSA call; legacy intact | After 1–2 weeks of dual sending |
| **3** | TSA only; legacy removed | Log warning; send without proof | Set `TSA_NOTIFICATION_PHASE=2` | After consumers confirm TST parsing works |

Control via env var: `TSA_NOTIFICATION_PHASE=2` (default) | `3`

> **Why two phases, not four:**
> The original design had Phase 3 and Phase 4 as separate stages, but they were
> code-identical — both sent TSA-only and both had no legacy fallback. Collapsing
> them eliminates a phantom distinction that would confuse the agent. If a future
> requirement emerges (e.g., "hard-fail: refuse to send notification if TSA is
> down"), add Phase 4 at that time with an explicit behavioral difference.

```typescript
/**
 * NOTIFICATION → TSA POLICY TIER MAPPING
 *
 * Repository: SigmaWolf-8/Ternary
 * Location:   server/services/notification-tsa-policy.ts
 *
 * Determines which TSA tier (COMPLY, FORENSICS, SENTINEL, etc.) applies
 * to each outbound notification based on channel and content type.
 * Separated from notification-service.ts for clean imports and testability.
 */

import { TSA_POLICIES, TSA_POLICY_METADATA } from './tsa-service';

// ── Channel-based default policy tiers ────────────────────────────────────
export const CHANNEL_POLICY: Record<string, string> = {
  email:    TSA_POLICIES.COMPLY,     // Most commonly subpoenaed business record
  sms:      TSA_POLICIES.DEFAULT,    // Transactional alerts
  push:     TSA_POLICIES.DEFAULT,    // Ephemeral notifications
  webhook:  TSA_POLICIES.SECURE,     // Machine-to-machine in zero-trust
  event:    TSA_POLICIES.SENTINEL,   // Internal events for timeline reconstruction
};

// ── Content-based policy overrides (take precedence over channel) ─────────
export const CONTENT_POLICY: Record<string, string> = {
  // Legal / eDiscovery
  'legal-notice':         TSA_POLICIES.FORENSICS,
  'litigation-hold':      TSA_POLICIES.FORENSICS,
  'ediscovery-alert':     TSA_POLICIES.FORENSICS,
  // Financial / Regulatory
  'trade-confirmation':   TSA_POLICIES.COMPLY,
  'regulatory-filing':    TSA_POLICIES.COMPLY,
  'audit-notification':   TSA_POLICIES.COMPLY,
  // Security / Incident
  'security-alert':       TSA_POLICIES.SENTINEL,
  'incident-response':    TSA_POLICIES.SENTINEL,
  'access-violation':     TSA_POLICIES.SENTINEL,
  // Document workflow
  'document-signed':      TSA_POLICIES.FORENSICS,
  'document-delivered':   TSA_POLICIES.FORENSICS,
  'document-rejected':    TSA_POLICIES.FORENSICS,
};

/**
 * Resolve the TSA policy OID for a notification.
 * Priority: content classification > channel default > global default.
 */
export function resolveTsaPolicy(
  channel: string,
  contentType?: string,
): string {
  if (contentType && CONTENT_POLICY[contentType]) {
    return CONTENT_POLICY[contentType];
  }
  return CHANNEL_POLICY[channel] || TSA_POLICIES.DEFAULT;
}

/**
 * Resolve the human-readable tier name for a policy OID.
 * Used for Prometheus labels and structured logging.
 *
 * Returns 'DEFAULT', 'COMPLY', 'FORENSICS', 'SENTINEL', or 'SECURE'.
 * Falls back to 'UNKNOWN' if OID not found in metadata.
 */
export function resolveTierName(
  channel: string,
  contentType?: string,
): string {
  const oid = resolveTsaPolicy(channel, contentType);
  const meta = TSA_POLICY_METADATA[oid];
  return meta?.tier || 'UNKNOWN';
}
```

### Method: acquireTsaToken (non-blocking, instrumented)

```typescript
/**
 * Request an RFC 3161 Time-Stamp Token for a notification payload.
 *
 * This is the core Phase 2 integration point:
 *   1. Hashes notification content with SHA-256
 *   2. Calls tsaService.processJsonRequest() (same-process, no HTTP)
 *   3. Returns base64 TST + metadata for header injection and audit
 *
 * On failure, returns null — NEVER blocks notification delivery.
 * Prometheus metrics are recorded for every outcome.
 */
private async acquireTsaToken(
  payload: string | Buffer,
  channel: string,
  contentType?: string,
): Promise<JsonTimestampResponse | null> {
  if (!this.tsaService) {
    tsaRequestCounter.inc({
      phase: String(TSA_PHASE),
      channel,
      policy_tier: 'none',
      status: 'skipped_no_service',
    });
    return null;
  }

  // Resolve tier name BEFORE the call — needed for error-path metrics
  // so the label value is consistent with the success path
  // (response.policyTier on success, this on error — both are tier NAMES)
  const tierName = resolveTierName(channel, contentType);

  const endTimer = tsaDurationHistogram.startTimer({
    phase: String(TSA_PHASE),
    channel,
    policy_tier: tierName,
  });

  try {
    // 1. Hash the payload with SHA-256
    //    SHA-256 (not SHA-3) because:
    //    - Universal default for RFC 3161 clients
    //    - OpenSSL ts -verify expects SHA-256 by default
    //    - SHA-3 still used in legacy headers if Phase 2 dual-mode
    const payloadBuffer = Buffer.isBuffer(payload)
      ? payload
      : Buffer.from(payload, 'utf-8');
    const hash = crypto.createHash('sha256')
      .update(payloadBuffer)
      .digest('hex');

    // 2. Resolve policy OID
    const policyOid = resolveTsaPolicy(channel, contentType);

    // 3. Nonce for replay protection (128-bit entropy)
    const nonce = crypto.randomBytes(16).toString('hex');

    // 4. Call TSA (same-process, no HTTP overhead)
    const response = await this.tsaService.processJsonRequest(
      {
        hash,
        algorithm: 'sha256',
        policy: policyOid,
        nonce,
        includeChain: false,  // Internal consumer — chain not needed in header, saves ~1-2KB
      },
      'notification-service',
    );

    // 5. Record metrics
    endTimer();
    tsaRequestCounter.inc({
      phase: String(TSA_PHASE),
      channel,
      policy_tier: response.policyTier,
      status: 'success',
    });
    tsaTokenSizeHistogram.observe(
      { policy_tier: response.policyTier },
      response.token.length,
    );

    // 6. Structured log
    console.info('TSA token acquired', {
      channel,
      contentType,
      serial: response.serialNumber,
      tier: response.policyTier,
      merkleLeaf: response.merkleLeafHash.slice(0, 16) + '...',
      tokenChars: response.token.length,
      phase: TSA_PHASE,
    });

    return response;

  } catch (err) {
    endTimer();

    const status = (err as Error).message.includes('timeout')
      ? 'timeout'
      : 'error';

    tsaRequestCounter.inc({
      phase: String(TSA_PHASE),
      channel,
      policy_tier: tierName,  // Tier NAME, not OID — matches success path labels
      status,
    });

    console.error('TSA token failed', {
      channel,
      contentType,
      error: (err as Error).message,
      phase: TSA_PHASE,
      fallback: TSA_PHASE <= 2 ? 'legacy' : 'none',
    });

    return null;
  }
}
```

### Method: buildProofHeaders

```typescript
/**
 * Build cryptographic proof headers for an outbound notification.
 *
 * Phase 2: Returns BOTH legacy headers AND TSA token header.
 * Phase 3: Returns TSA token header only.
 *
 * TSA failure NEVER blocks delivery — Phase 2 falls back to legacy,
 * Phase 3 sends without proof and logs the gap.
 */
private async buildProofHeaders(
  payload: string | Buffer,
  channel: string,
  contentType?: string,
): Promise<Record<string, string>> {
  const headers: Record<string, string> = {};

  // ── Attempt TSA token acquisition ────────────────────────────────────
  const tsa = await this.acquireTsaToken(payload, channel, contentType);

  if (tsa) {
    // ── TSA token acquired ─────────────────────────────────────────────
    // Primary header: base64 RFC 3161 TimeStampResp
    // Contains: trusted time + hash proof + classical sig + TL-DSA dual-sig
    // Verifiable: openssl ts -verify -in <token> -CAfile plenumnet-tsa.pem
    headers['X-PlenumNET-TSA-Token'] = tsa.token;

    // Metadata headers (same data is in the TST, but these save a DER parse)
    headers['X-PlenumNET-TSA-Serial'] = tsa.serialNumber;
    headers['X-PlenumNET-TSA-GenTime'] = tsa.genTime;
    headers['X-PlenumNET-TSA-Policy'] = tsa.policyTier;
    headers['X-PlenumNET-TSA-Merkle'] = tsa.merkleLeafHash;

    // Header size safety check
    // tsa.token is a base64 STRING — .length gives the actual character count
    // the MTA will see in the header. Most MTAs allow 100+ KB total headers.
    // RFC 5322 recommends individual lines under 998 chars; fold if needed.
    if (tsa.token.length > 4096) {
      console.warn('Large TST detected', {
        tokenChars: tsa.token.length,
        serial: tsa.serialNumber,
        tier: tsa.policyTier,
        note: 'Consider header folding per RFC 5322 §2.2.3',
      });
    }

    if (TSA_PHASE === 2) {
      // Phase 2: Also send legacy headers for backward compatibility
      const legacy = await this.buildLegacyHeaders(payload);
      Object.assign(headers, legacy);
      headers['X-PlenumNET-Proof-Mode'] = 'tsa+legacy';
    } else {
      headers['X-PlenumNET-Proof-Mode'] = 'tsa-only';
    }

  } else {
    // ── TSA unavailable ────────────────────────────────────────────────

    if (TSA_PHASE <= 2) {
      // Phase 2: Fall back to legacy headers (same as Phase 1 behavior)
      const legacy = await this.buildLegacyHeaders(payload);
      Object.assign(headers, legacy);
      headers['X-PlenumNET-Proof-Mode'] = 'legacy-fallback';
    } else {
      // Phase 3: No legacy fallback exists
      headers['X-PlenumNET-Proof-Mode'] = 'none';
      console.warn('TSA unavailable in Phase 3 — notification sent without proof', {
        channel,
        contentType,
        phase: TSA_PHASE,
      });
    }
  }

  return headers;
}
```

### Method: buildLegacyHeaders (Phase 1 preservation)

```typescript
/**
 * Build the original Phase 1 cryptographic headers.
 *
 * AGENT: If notification-service.ts ALREADY has a method that builds
 * these three headers (possibly named buildHeaders, prepareHeaders,
 * getTimestampHeaders, or inline in the send method), RENAME that
 * existing method to buildLegacyHeaders and use it here. Do NOT
 * duplicate the logic.
 *
 * If the existing code builds these headers INLINE (not in a method),
 * EXTRACT the logic into this method and call it from both the
 * original location and from buildProofHeaders.
 *
 * The implementation below is the reference — adapt to match existing
 * client method names and error handling patterns.
 */
private async buildLegacyHeaders(
  payload: string | Buffer,
): Promise<Record<string, string>> {
  const headers: Record<string, string> = {};

  try {
    // 1. HPTP trusted timestamp
    const hptpResult = await this.hptpClient.getTimestamp();
    headers['X-PlenumNET-HPTP-Timestamp'] = hptpResult.timestamp;

    // 2. SHA-3 hash of notification content
    const payloadBuffer = Buffer.isBuffer(payload)
      ? payload
      : Buffer.from(payload, 'utf-8');
    const messageHash = crypto.createHash('sha3-256')
      .update(payloadBuffer)
      .digest('hex');
    headers['X-PlenumNET-Message-Hash'] = messageHash;

    // 3. TL-DSA post-quantum signature of the hash
    try {
      const sig = await this.tldsaClient.sign(messageHash);
      headers['X-PlenumNET-TLDSA-Signature'] = sig.signature;
      headers['X-PlenumNET-TLDSA-KeyId'] = sig.publicKeyId;
    } catch {
      // TL-DSA failure is non-fatal (same policy as TSA dual-sign)
    }
  } catch (error) {
    console.error('Legacy header build failed', {
      error: (error as Error).message,
    });
  }

  return headers;
}
```

### Label Consistency Note

Both success and error paths emit `policy_tier` as a human-readable tier
name (`COMPLY`, `FORENSICS`, `SENTINEL`, etc.), NOT the raw OID. This is
handled by `resolveTierName()` in the policy file, which does a reverse
lookup through `TSA_POLICY_METADATA`. Consistent label values prevent
cardinality explosions in Prometheus.

## CONSUMER VERIFICATION GUIDE

```bash
# ── Step 1: Extract token from email header ─────────────────────────────
echo "$X_PlenumNET_TSA_Token" | base64 -d > notification.tsr

# ── Step 2: Download PlenumNET TSA certificate (one-time) ───────────────
curl https://plenumnet.replit.app/api/tsa/certificate/download -o plenumnet-tsa.pem

# ── Step 3: Hash the exact notification content received ────────────────
sha256sum received-body.txt   # copy the hex digest

# ── Step 4: Verify ──────────────────────────────────────────────────────
openssl ts -verify \
  -digest <paste-sha256-hex-here> \
  -in notification.tsr \
  -CAfile plenumnet-tsa.pem

# Expected: Verification: OK
#
# This proves:
#   1. The notification existed at TSTInfo.genTime (HPTP-sourced)
#   2. It was signed by PlenumNET's TSA key (not forged)
#   3. The serial links to PlenumNET's Merkle audit log
#   4. Content has not been modified since timestamping
```

## CONSUMER MIGRATION EMAIL

**Subject:** PlenumNET Notification Headers — Migration to RFC 3161 Time-Stamp Token

---

Dear [Team / Integration Partner],

We are upgrading the cryptographic proof mechanism on all outbound PlenumNET
notifications — email, webhook, and event bus — to use a single, standards-compliant
RFC 3161 Time-Stamp Token in place of the three legacy proprietary headers.

**What is changing**

One verifiable token (`X-PlenumNET-TSA-Token`) replaces three separate headers
(`X-PlenumNET-HPTP-Timestamp`, `X-PlenumNET-Message-Hash`, `X-PlenumNET-TLDSA-Signature`).
The new token is offline-verifiable with standard tools — OpenSSL, Adobe Acrobat,
jarsigner — with no dependency on PlenumNET infrastructure. It includes serial number,
Merkle audit linkage, policy tier classification, and hybrid post-quantum dual-signing.

**Timeline**

| Phase | Target Date | What Happens |
|-------|------------|-------------|
| Phase 2 (current) | Now | Both legacy headers AND new TSA token are sent. No action required yet. |
| Phase 3 | [Date + 3 weeks] | Legacy headers removed. Only TSA token sent. |

During Phase 2, you can continue using the legacy headers while preparing your
consumer logic. We recommend switching to the TSA token as early as possible.

**What you need to do**

Update your verification logic to parse `X-PlenumNET-TSA-Token` (a base64-encoded
RFC 3161 TimeStampResp). Verification with OpenSSL:

```
# Extract token from header
echo "$TOKEN" | base64 -d > notification.tsr

# Download our TSA certificate (one-time)
curl https://plenumnet.replit.app/api/tsa/certificate/download -o plenumnet-tsa.pem

# Hash the exact notification body received
```

## NON-NEGOTIABLE RULES

1. **TSA failure NEVER blocks notification delivery.** `acquireTsaToken` is wrapped in try-catch. Phase 2 falls back to legacy; Phase 3 sends without proof. Log the failure; never throw.

2. **Phase 2 is additive only.** No existing functionality removed or changed. Legacy headers continue to be built the same way. TSA token is added alongside.

3. **Policy tier mapping is deterministic.** Same channel + content type always produces the same OID. No randomness, no per-user overrides.

4. **Prometheus labels are consistent.** `policy_tier` is always a tier NAME (COMPLY, FORENSICS, etc.), never a raw OID, in both success and error paths.

5. **The notification service does NOT parse TSA tokens.** It treats the base64 string as opaque. TSA service handles all ASN.1/CMS internally.

6. **Cross-reference serial numbers.** Every notification delivery log entry includes the TSA serial. Two-way audit trail: notification → TSA and TSA → notification.

7. **Environment variable controls phase.** `TSA_NOTIFICATION_PHASE` is the only switch. No code changes to advance.
