Finding F2-R: Kernel Cargo.toml Files Still Declare MIT License
Severity: CRITICAL
Files Affected: src/kernel/Cargo.toml (line 8) and src/kernel/wasm/Cargo.toml (line 7)
The main kernel crate (plenumnet-kernel) and the WASM interface crate (plenumnet-wasm) both still declare license = "MIT" in their Cargo.toml manifests. This is the most valuable component of the entire IP portfolio — approximately 47,230 lines of Rust code comprising the cryptographic engine, virtual machine, memory subsystem, network stack, and FIPS compliance modules. Remediation: Phase 0, Tasks 0-1 and 0-2. Change license = "MIT" to license = "LicenseRef-Proprietary" in both files. Push via GitHub API immediately.

4. New Findings (Post-Original Audit)
Finding NF-1: 522 Rust Build Artifacts Tracked in Git (280 MB)
Severity: CRITICAL
Source: Third-Party Engineering Review
The directory src/kernel/target/ contains 522 compiled Rust artifacts (.rlib, .rmeta, .so, .d files) totaling approximately 280 MB. These are debug build outputs that should never be committed to version control. The root .gitignore contains target/ but this only matches a top-level target/ directory — it does not match the nested src/kernel/target/ path because the files were added to git tracking before the .gitignore rule existed. GitHub is already issuing file size warnings for objects exceeding 50 MB.
Impact: Every clone of the repository downloads 280 MB of useless binaries. This slows CI/CD pipelines, increases storage costs, and creates a poor first impression for any technical due diligence reviewer.
Remediation: Phase 0, Tasks 0-4 and 0-5. Remove from tracking with git rm -r --cached, update .gitignore to use **/target/ glob, and force-push the cleaned history.
Finding NF-2: Incorrect Jurisdiction in 3 Legal Documents
Severity: CRITICAL
Source: Third-Party Engineering Review
Three internal legal documents reference Ontario as the governing jurisdiction instead of the Province of Alberta, which is the correct incorporation jurisdiction for Capomastro Holdings Ltd. under the Alberta Business Corporations Act:
•	INTERNAL-IP-STRATEGY.md — "Ontario governing law"
•	COMPONENT-LICENSING-MATRIX.md — "Ontario governing law" (2 references)
•	ENTERPRISE-SLA.md — "Province of Ontario" for governing law and courts
While these files are listed in .gitignore and should not be in the public repository, if they exist in any working copy or have ever been committed, the jurisdictional inconsistency creates a material risk: if an enterprise customer signs an SLA with Ontario as governing law while the LICENSE file specifies Alberta, a conflict-of-laws issue arises that could void key protections.
Remediation: Phase 0, Task 0-6. Correct all jurisdiction references to Province of Alberta in all three documents. If these files are only local, update them locally. If they were ever committed, verify they are not in git history.

7. Security Findings
SEC-1: No Server-Side Rate Limiting Middleware
Severity: HIGH
Rate limit configurations appear in route metadata (for Kong gateway docs) but NO actual rate limiting middleware exists in the Express application. The server is directly exposed at PlenumNET.replit.app without Kong or any API gateway in front. All 81 API endpoints are unprotected against abuse, brute force, or denial-of-service.
Remediation: Phase 2, Task 2-1.
SEC-2: No CORS Configuration
Severity: MEDIUM
No CORS headers or middleware are configured. The server accepts requests from any origin. For a platform with authentication and GitHub token management, this creates cross-origin request forgery risk.
Remediation: Phase 2, Task 2-2.
SEC-3: No Helmet.js Security Headers
Severity: MEDIUM
No security headers configured (X-Content-Type-Options, X-Frame-Options, HSTS, CSP, etc.). These are baseline requirements for any production web application.
Remediation: Phase 2, Task 2-3.
SEC-4: child_process exec() in Kong Certificate Generation
Severity: MEDIUM
Location: server/routes.ts, line 3348
The Kong certificate generation route uses exec() with string interpolation to call openssl. While parameters are currently hardcoded, exec() invokes a shell and is susceptible to injection if any parameter becomes user-influenced in future modifications.
Remediation: Phase 2, Task 2-4.
SEC-5: sanitizePath Vulnerable to Encoded Path Traversal
Severity: MEDIUM
Location: server/routes.ts, line 1931
The sanitizePath function uses regex to remove ".." sequences but does not handle URL-encoded traversal (%2e%2e%2f) or double-encoding. While GitHub's API provides a second layer of defense, defense-in-depth requires proper path normalization.
Remediation: Phase 2, Task 2-5.
SEC-6: GitHub Tokens Stored Without Encryption-at-Rest
Severity: HIGH
GitHub Personal Access Tokens are stored via storage.updateUserGithubToken(). If the Drizzle/PostgreSQL storage uses no column-level encryption, tokens are plaintext in the database. The project already has AES-256-GCM encryption utilities in services/payment-listener/config/secrets-config.ts that should be reused.
Remediation: Phase 2, Task 2-6.
SEC-7: No Input Validation Bounds on Numeric Parameters
Severity: MEDIUM
Several endpoints accept unbounded numeric parameters (batch timestamp count, pagination sizes, trit counts). A request for count=1000000 could cause memory exhaustion.
Remediation: Phase 2, Task 2-7.
8. Code Quality & Bug Risk Assessment
BUG-1: Monolithic Routes File (3,732 Lines)
Severity: HIGH (Maintenance Risk)
server/routes.ts contains ALL 81 API routes, all middleware, all GitHub integration, all Kong management, all ternary computation, all calendar conversion, and all legal document serving in a single file. This is the single biggest maintenance risk in the codebase.
Remediation: Phase 3, Task 3-1.
BUG-2: Critically Low Test Coverage
Severity: CRITICAL (Quality Risk)
Only 6 test files exist for a 70,000+ line codebase. Zero tests for: phase encryption round-trip, GF(3) arithmetic correctness, API route input validation, calendar conversion accuracy, compression layer, GitHub API integration, authentication flows, or Kong management operations. For FIPS 140-3 certification, comprehensive self-tests and known-answer tests (KATs) are mandatory.
Remediation: Phase 4, Tasks 4-1 through 4-6.
BUG-3: Excessive use of catch (error: any)
Severity: MEDIUM
50+ catch blocks use error: any which defeats TypeScript type safety. Errors should be typed as unknown with instanceof narrowing.
Remediation: Phase 3, Task 3-2.
BUG-4: Console Logging in Production
Severity: LOW
33 console.log/error/warn calls bypass the structured log() utility, resulting in unformatted production logs.
Remediation: Phase 3, Task 3-3.
BUG-5: Unbounded Batch Operations
Severity: MEDIUM
The batch timestamp endpoint (GET /api/salvi/timing/batch/:count) accepts a user-supplied count with no upper bound. Same pattern exists in other batch endpoints.
Remediation: Addressed by SEC-7 / Phase 2, Task 2-7.

10. GitHub API Push Protocol
All tasks in this document specify file paths that must be updated via the GitHub Contents API. The standard workflow for each file modification is:
1.	GET the current file to obtain its SHA: GET /repos/SigmaWolf-8/Ternary/contents/{path}?ref=main
2.	Base64-encode the new file content.
3.	PUT the updated file: PUT /repos/SigmaWolf-8/Ternary/contents/{path} with body: { message, content (base64), sha, branch: "main" }
4.	For new files, omit the sha field in the PUT request body.
5.	For deletions, use DELETE /repos/SigmaWolf-8/Ternary/contents/{path} with the file's current SHA.
The PlenumNET application has this workflow implemented at PUT /api/github/file/:owner/:repo (server/routes.ts line 2071). Use this endpoint with a valid admin session, or make direct GitHub API calls with the configured Personal Access Token.
Exception — Task 0-4 (Build Artifact Removal): Directory-level removal from git history cannot be accomplished via the Contents API. This task requires either: (a) an authenticated local clone with git rm -r --cached and force-push, or (b) use of the GitHub Git Data API to reconstruct the tree/commit objects without the target/ directory.
