# Code Signing Procedures

## Overview

This document defines the code signing procedures for the PlenumNET/Salvi Framework. All release artifacts, kernel binaries, and compliance-critical modules require cryptographic signatures to verify authenticity and integrity.

---

## Key Management

### Key Types

| Key Type | Algorithm | Purpose | Rotation Period |
|----------|-----------|---------|-----------------|
| Release Signing | Ed25519 (SSH) or RSA-4096 (GPG) | Sign release tags and binaries | Annual |
| Commit Signing | Ed25519 (SSH) or RSA-4096 (GPG) | Sign git commits | Annual |
| SBOM Signing | Ed25519 | Sign Software Bill of Materials | Per release |
| Kernel Module Signing | Ed25519 | Sign kernel `.rlib` artifacts | Per release |

### Key Generation

#### GPG Key (RSA-4096)

```bash
gpg --full-generate-key
# Select: RSA and RSA
# Key size: 4096
# Expiration: 1 year
# Real name: PlenumNET Release Signing
# Email: security@plenumnet.io
```

#### SSH Key (Ed25519)

```bash
ssh-keygen -t ed25519 -C "release-signing@plenumnet.io" -f keys/signing/release-key
```

### Key Storage

| Location | Access | Contents |
|----------|--------|----------|
| GitHub Secrets | CI/CD only | `GPG_SIGNING_KEY`, `GPG_PASSPHRASE` |
| Hardware Security Module (HSM) | Maintainers only | Master signing keys |
| `keys/signing/` (repo) | Public | Public keys only, `.gitignore` blocks private keys |
| Offline backup | Security team | Encrypted key backups |

**CRITICAL**: Private keys must NEVER be committed to the repository. The `.gitignore` file must include:

```
keys/signing/*.pem
keys/signing/*.key
keys/signing/*-private*
keys/signing/*.gpg
!keys/signing/*.pub
!keys/signing/*.md
```

## Signing Procedures

### 1. Release Tag Signing

All release tags must be signed:

```bash
git tag -s v1.0.0 -m "Release v1.0.0: CNSA 2.0 Full Compliance"
git push origin v1.0.0
```

Verify:

```bash
git tag -v v1.0.0
```

### 2. Commit Signing

Configure Git for automatic commit signing:

```bash
git config --local commit.gpgsign true
git config --local user.signingkey <KEY_ID>
```

For SSH signing (GitHub-recommended):

```bash
git config --local gpg.format ssh
git config --local user.signingkey ~/.ssh/id_ed25519.pub
```

### 3. Release Artifact Signing

For each release binary, generate a detached signature:

```bash
gpg --armor --detach-sign --output kernel-x86_64.sig kernel-x86_64.bin
sha256sum kernel-x86_64.bin > kernel-x86_64.sha256
```

### 4. Kernel Module Signing

Kernel crypto modules require individual signatures for CNSA 2.0 compliance:

```bash
# Sign each critical module
for module in tl_kem tl_dsa cipher sha2 sha3 cnsa2; do
  gpg --armor --detach-sign \
    --output "signatures/${module}.rs.sig" \
    "src/kernel/src/crypto/${module}.rs"
done
```

### 5. SBOM Signing

The CycloneDX SBOM generated by `security-scan.yml` must be signed:

```bash
gpg --armor --detach-sign --output sbom.cdx.json.sig sbom.cdx.json
```

## Key Rotation

### Annual Rotation Process

1. Generate new signing key pair
2. Sign new public key with old key (key transition signature)
3. Update GitHub Secrets with new key
4. Publish key transition notice in SECURITY.md
5. Revoke old key after 90-day overlap period

### Emergency Rotation (Key Compromise)

1. Immediately revoke compromised key on key servers
2. Generate new key pair
3. Re-sign all current release artifacts
4. Publish security advisory (CVE if applicable)
5. Update all CI/CD secrets
6. Notify users via release notes and SECURITY.md

## Verification

### Public Key Distribution

Public keys are distributed via:

1. Repository: `keys/signing/release-signing.pub`
2. GitHub profile: Maintainer verified signing keys
3. Key server: `keys.openpgp.org`

### Verifying Releases

```bash
# Import public key
gpg --import keys/signing/release-signing.pub

# Verify release tag
git tag -v v1.0.0

# Verify binary
gpg --verify kernel-x86_64.sig kernel-x86_64.bin

# Verify checksum
sha256sum -c kernel-x86_64.sha256
```

## CI/CD Integration

The `release.yml` workflow automates signing for tagged releases:

1. Imports GPG key from `GPG_SIGNING_KEY` secret
2. Signs all build artifacts
3. Generates and signs SBOM
4. Attaches signatures to GitHub Release

Required secrets:

| Secret | Description |
|--------|-------------|
| `GPG_SIGNING_KEY` | Base64-encoded private key |
| `GPG_PASSPHRASE` | Key passphrase |
