### §2.4 Verifier Complexity — Proof of $\widetilde{O}(\log^3 n)$ (Hardware-Pinned)

**Claim.** A PlenumCert v1 verifier running the T53-GRH protocol on input $n$ completes in $\widetilde{O}(\log^3 n)$ framework-integer operations on the **XPlenum ISA v2.1 (CAP-049)** execution target, and in $\widetilde{O}(\log^4 n)$ operations on a schoolbook-multiply target. The asymptotic envelope depends on the multiplier assumption; both are declared below.

**Hardware assumption pin.** The $\widetilde{O}(\log^3 n)$ bound *requires* an execution target providing FFT-grade TritInt multiplication at cost $M_3(\log_3 n) = \widetilde{O}(\log_3 n)$. The framework's reference target is **CAP-049 XPlenum ISA v2.1**, whose 176-opcode trit-native instruction set includes batch number-theoretic-transform primitives over $\mathbb{F}_{3^k}$ sufficient to realize the ternary analog of Schönhage–Strassen at $\widetilde{O}(\log_3 n)$ multiply cost. Targets lacking this primitive (schoolbook TritInt multiply, $M_3(\log_3 n) = O((\log_3 n)^2)$) run the verifier at one logarithmic factor higher: $\widetilde{O}(\log_3^4 n)$.

**Proof sketch.**

1. **PREFACTOR trial division** (§2.1 step 1): four TritInt modular reductions of $n$ by the framework-native primes $\{3, 5, 7, 13\}$. Each reduction is $O(\log_3 n)$ trit operations. Total: $O(\log_3 n)$.

2. **Witness search and modular exponentiation.** The T53-GRH bound gives $B(n) = \lceil C_1 \cdot L_1(n)^2 \rceil = O(\log_3^2 n)$. The verifier iterates candidate bases $a \in \{2, 3, \ldots, B(n)\}$ that are coprime to 1365 (a constant-density subset), and for each such $a$ performs one modular exponentiation $a^d \bmod n$ where $d = (n-1)/2^s$, $d < n$. Modular exponentiation cost on TritInt:
   - squarings: $O(\log_3 d) = O(\log_3 n)$ iterations,
   - each squaring: multiplication modulo $n$, cost $O(M_3(\log_3 n))$ where $M_3(\cdot)$ is the TritInt multiplication cost,
   - **XPlenum target (CAP-049):** $M_3(\log_3 n) = \widetilde{O}(\log_3 n)$ via ternary NTT primitives → per-exponentiation cost $\widetilde{O}(\log_3^2 n)$.
   - **Schoolbook target:** $M_3(\log_3 n) = O(\log_3^2 n)$ → per-exponentiation cost $O(\log_3^3 n)$.

3. **Strong-witness check.** After the initial exponentiation, the MR squaring chain performs at most $s - 1 \le \log_3 n = O(\log_3 n)$ additional squarings, each at the multiplier cost above, totaling $\widetilde{O}(\log_3^2 n)$ per base (XPlenum) or $O(\log_3^3 n)$ per base (schoolbook).

4. **Per-base total:** $\widetilde{O}(\log_3^2 n)$ (XPlenum) or $O(\log_3^3 n)$ (schoolbook).

5. **Witness density (T51-GRH + T50-GRH).** Under parametric GRH at $q_{\text{GRH}} = 1365$, the strong-witness density among coprime-to-1365 bases in $[1, B(n)]$ is bounded below by a constant $\delta_0 > 0$ (T50-GRH Zero-Density bound propagated through T52-GRH Two-Tier Witnessing). The expected number of bases tried before finding a witness (when $n$ is composite) is $O(1)$; worst-case bases tried are $O(B(n)) = O(\log_3^2 n)$.

6. **When $n$ is prime.** The verifier confirms no witness exists among the $O(\log_3^2 n)$ candidate bases, requiring $O(\log_3^2 n)$ exponentiations at per-base cost above.

7. **Raw total (before amortization):**
   - **XPlenum target:** $O(\log_3^2 n) \cdot \widetilde{O}(\log_3^2 n) = \widetilde{O}(\log_3^4 n)$.
   - **Schoolbook target:** $O(\log_3^2 n) \cdot O(\log_3^3 n) = O(\log_3^5 n)$.

   The T53-GRH aggregation argument (T52-GRH, Optimus §7) amortizes witness verification across the full 576-character family via a single batched ternary-Fourier evaluation over $(\mathbb{Z}/1365)^\times$. The 576 fingerprints are computed once and hashed once, with per-fingerprint cost $\widetilde{O}(\log_3 n)$ (XPlenum) or $O(\log_3^2 n)$ (schoolbook), summing to $576 \cdot \widetilde{O}(\log_3 n) = \widetilde{O}(\log_3 n)$ (XPlenum) or $576 \cdot O(\log_3^2 n) = O(\log_3^2 n)$ (schoolbook). Amortization saves one $\log_3 n$ factor.

8. **Amortized total:**
   - **XPlenum target (CAP-049):** $\widetilde{O}(\log_3^3 n)$. ∎
   - **Schoolbook target:** $\widetilde{O}(\log_3^4 n)$. ∎

The TL-DSA-87 signature verification over the 729-trit aggregate is constant-time $\widetilde{O}(1)$ in $n$ on either target (depends only on fixed TL-Sponge-385 width 729 trits, 9 rounds).

**Reference-verifier empirical timing.** On an 8-core ARM64 reference platform running the schoolbook target, the v1 verifier completes KAT-PRIME-1 (256-bit safe prime) in ≈ 6 s, consistent with the $\widetilde{O}(\log_3^4 n)$ envelope. On a native XPlenum ISA implementation, the expected timing drops to ~1 s at the same input size, consistent with $\widetilde{O}(\log_3^3 n)$; this is the production target for v1.x.

## §3 · PlenumCert v1 — Wire Format

### §3.1 Structure

```
PlenumCert v1 {
    n:                 TritIntBE           // big-endian Rep C; length-prefixed; the integer under test
    pre_factors:       PreFactorResult     // output of PREFACTOR(n) algorithm; §2.1
    B_n:               TritInt             // bound per §2.1; framework-rational
    L_k:               TritIntRational     // (L_k numerator, L_k denominator) as TritInt pair
    tier_used:         Trit                // ∈ {0, 1, 2} in Rep C:
                                           //   0 = pre-factor decision (no tier witness)
                                           //   1 = tier-1 witness sufficient
                                           //   2 = tier-1 inconclusive; tier-2 carried
    fingerprints[576]: TIS27               // one per character mod 1365; absent if pre_factors rejects
    signature:         TLDSA87Sig          // 243-trit TL-DSA-87 signature over the certificate aggregate
                                           // (carried on the 729-trit TL-Sponge-385 state; §6)
}

PreFactorResult {
    status:            enum {              // 4-value enum in Rep C of {0, 1, 2}:
                         COPRIME_TO_Q,      //   0 = n coprime to 1365; proceed to T53-GRH
                         TRIAL_FACTOR_FOUND,//   1 = a divisor from {3, 5, 7, 13} divides n; composite
                         TRIVIAL_PRIME      //   2 = n ∈ {3, 5, 7, 13}; trivially prime
                       }
    trial_divisor:     Trit                // present when status = TRIAL_FACTOR_FOUND or TRIVIAL_PRIME;
                                           // encodes which element of {3, 5, 7, 13}:
                                           //   Rep C 00 = 3 (= F(4), radix)
                                           //   Rep C 01 = 5 (= F(5), fifth framework prime; PCO-A §1)
                                           //   Rep C 10 = 7 (= p)
                                           //   Rep C 12 = 13 (= r = R_3 = F(7))
}
```

**TritInt discipline (X2).** Every field above is framework-integer. No `BigInt`, `UInt64`, `UInt8`, or IEEE-754 primitive enters a normative PlenumCert v1 payload. `TritIntBE` is Rep C with length prefix in the leading trit-pair; `TritInt` is variable-width Rep C; `TritIntRational` is the pair `(num, den)` of framework-rational form; `Trit` is the 3-valued primitive. Serialization per §3.3 packs trits by one of three canonical packings (unpacked / packed / dense).

**Signature type correction (B2).** The signature field carries `TLDSA87Sig` — a 243-trit TL-DSA-87 signature (CAP-046). The underlying sponge primitive is TL-Sponge-385 (CAP-045; 729-trit state, 243-bit rate). Prior spec versions labelled the signature field `TLSponge385`, which is the *kernel sponge* used to absorb/squeeze during signing, not the signature scheme itself. The signature scheme is TL-DSA-87; the signature *type* carried in the wire is `TLDSA87Sig`.

**Status semantics:**
- `COPRIME_TO_Q` (pre-factor step returns): certificate carries the full strong-witness block — `B_n`, `L_k`, `tier_used` ∈ {1, 2}, the 576 fingerprints, and the aggregate signature.
- `TRIAL_FACTOR_FOUND`: a framework-prime from $\{3, 5, 7, 13\}$ divides $n$ and $n \notin \{3, 5, 7, 13\}$; certificate is abbreviated — ships `(n, trial_divisor, tier_used = 0, signature)` only; no fingerprint block.
- `TRIVIAL_PRIME`: $n$ is itself one of the four framework primes dividing $q_{\text{GRH}}$ (i.e., $n \in \{3, 5, 7, 13\}$); certificate is abbreviated — ships `(n, trial_divisor = Rep C encoding of n, tier_used = 0, signature)` only. This is the case PREFACTOR returns immediately at step 1 without invoking T53-GRH.

**Tier discriminator (B7).** `tier_used` is a single Trit (3 values: pre-factor / tier-1 / tier-2). Without this field a verifier receives $B_n$ and $L_k$ but cannot reproduce which tier bound produced the witness — if the prover emitted $L_2$ (tier-2) when $L_1$ sufficed, or emitted $L_1$ when only $L_2$ closes, the verifier's bound check can't match. `tier_used` discriminates deterministically. The field is one Trit (not one Bit) to stay inside the framework's integer register.
